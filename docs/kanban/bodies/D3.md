评审遗留 · D3：数据集删除的级联下沉到 store 层

## 目标
数据集软删时，通道/指标值/超限记录的级联目前散在页面或 pipeline 里，改为在 `store/datasets.py` 内统一完成。

## 验收标准
- 单测：软删数据集后，其通道、指标值都不再出现在查询结果里；超限记录同步不可见。
- 页面层不再自己写级联逻辑。
- 全量 `pytest tests` 通过。

## 铁律（马哥要求，必须遵守）
- 只做本任务列出的范围，不自行加功能、不顺手扩展。
- 严格 TDD：先写测试 → 跑出 RED → 实现 → 跑出 GREEN；不得跳过、不得伪造结果。
- 结果以真实命令输出为准，Report 里必须贴真实测试通过数。
- 写新代码前先确认 GitHub 上是否已有成熟方案，没有才自研，并在提交信息里写明选型。
- 完成后执行：`ruff format` → `ruff check` → `pytest tests` → `git commit`（中文提交信息）。
- 改到 `app/` 或 `src/` 后重启 Streamlit：先 pgrep 找实例、kill 旧的，再后台起 8501。
- 若发现 `git status` 出现不是自己造成的改动 → 立即停手，在结论里说明冲突，不要覆盖别人。
- 不碰「待确认」项（指标参数配置方式、有效性判据、量程单位、告警推送、回收站保留期、批次分组、轴承频率库）。
- 交付物放项目目录内，不要往 ~/workspace 根目录写文件。

## 不要做
- 不要重构与本任务无关的代码。
- 不要改方案文档以外的东西；若实现与方案文档不一致，同步更新 `docs/plans/2026-10-28-监测软件方案与UI设计.md`。

## 页面实测的统一做法（2026-10-30 追加，避免重复踩坑）
- 起服务只用一条命令：`bash scripts/dev_serve.sh 8599` → 输出 `READY pid=… url=http://127.0.0.1:8599`；幂等，会自动停掉占用端口的旧进程。
- 验证用 `browser_exec` 访问 `http://127.0.0.1:8599`，不要自己 `streamlit run` 起服务，也不要 `pkill -f`（会被安全策略拦）。
- 验证完不用停服务，下一个任务复用同一端口即可。
- `pytest tests` 全量约 65 秒，一次跑完就够，不要重复跑；改动集中后再跑。
