# 健康树 ⟷ 基础配置表 职责梳理（2026-11-02）

> 马哥口径：
> 1. **基础配置表负责「自由状态」的增删改查，装配关系主要在健康树上进行**；每一级节点能增删与自定义设置，装配时不要反复跳回基础配置表页面。
> 2. **额定转速应该挂在「监测对象」节点，现在挂在通道节点上 —— 不对。**
> 3. **指标配置应下放到「指标」节点，不要在通道节点上。**

---

## 一、现状（已逐项核实，非推测）

### 1.1 三层结构

| 层 | 表 | 行数（正式库） | 职责 |
|---|---|---|---|
| ① 台账（主数据，可自由存在） | `monitor_object` / `channel_reg` / `sensor` / `metric_def` | 对象 4、通道 4、传感器 4、指标定义 3 | 数据 CRUD + 归属绑定 |
| ② 装配（健康树） | `task_node` | 通道节点 3、指标节点 9 | 层级 + 引用（`ref_type`+`ref_id`）|
| ③ 业务（挂节点） | `metric_assign` / `metric_limit` / `metric_value` | 参数绑定 9 条、指标值 N | 参数、阈值、指标值 |

### 1.2 现在的引用规则

- 节点 → 台账：`task_node.ref_type` + `ref_id`（component→monitor_object、channel→channel_reg、metric→metric_def），**一律用 ID**；节点名是 `sync_ref_name()` 维护的显示缓存。
- 台账改名 → 节点名同步；台账删除 → 节点变"悬空引用"并告警。
- 删节点 ≠ 删台账：对象/通道回"未装配"；通道节点上的传感器连带进回收站（可恢复）。
- 通道归属 = `channel_reg.object_id`（可空=自由通道）；传感器归属是绑定关系，可在「传感器」页改绑/解绑。

### 1.3 两个挂错位置的现状（你说的"不对"）

| 项目 | 现在挂在哪 | 证据 |
|---|---|---|
| **额定转速** | 通道节点手填（`tree.attrs['rpm']`） | `app/metric_params_ui.py:418-434`「本节点转速」+「保存转速」→ `metric_assign.set_node_rpm(channel_node.id)` |
| 对象额定转速（正确归属） | `monitor_object.rated_rpm`，**但四个对象全为 NULL，且没有任何界面能录** | `object_registry.set_rated_rpm()` 存在但无人调用 |
| **指标参数** | 通道节点 × 指标码（`metric_assign.node_id` = **通道节点 id**） | 9 条绑定全部指向 node 4 / 13 / 18（都是 channel 节点）|

**后果**：指标节点现在是空壳——只有 `ref_id` 指向指标定义、`attrs` 里存个 `code`，本身没有任何可配置项；而参数、阈值、指标值全挂在通道上。层级越往下越"空"，配置全挤在通道这一级，也不符合"指标自己有自己的算法参数"的直觉。

### 1.4 转速取值链路（现状）

`节点手填 > 批次实测(dataset.measured_rpm) > 对象额定(monitor_object.rated_rpm)`，都没有则"无转速"（不猜）。当前**手填在通道节点**，且 `tree.node_rpm()` 会往上继承 3 级——等于把"对象级属性"错放在通道级。

## 二、痛点：装配时必须跳页

| 要做的事 | 现在只能在 | 被迫跳去 |
|---|---|---|
| 树上加「监测对象」节点 | 从台账下拉里**选已有** | 监测对象页新建对象 |
| 树上加「通道」节点 | 从该对象名下**选已有通道** | 监测对象页给对象加通道 |
| 给通道录传感器 | 健康树只读展示 | 传感器页新建 |
| 给通道设阈值 | 无入口 | 阈值设置页 |
| 树上加「指标」节点 | 从指标定义选（3 个内置够用） | 指标配置页（仅自定义时要）|
| 节点改名 / 属性 / 频率覆盖 | ✅ 树上直接改 | — |

四级节点里只有「设备」能凭空新建（它没有台账），其余三层都得先去台账页"烧砖"，再回来"砌墙"。

## 三、目标分工

| | 基础配置表（台账页） | 健康树 |
|---|---|---|
| 定位 | **自由态仓库**：数据本身的生命周期 | **装配 + 节点设置**：层级、引用、节点自己的参数 |
| 做 | 对象/通道/传感器/指标定义的增删改查；归属绑定（自由⇄对象）；批量导入与批量操作；「已装配/未装配」视图 | 各级节点增删；就地新建并装配；节点参数（转速在对象节点、指标参数在指标节点、阈值在通道节点）；改名、属性、删除 |
| 不做 | 不碰装配层级 | 不重复维护台账字段（只引用，不双写）|

**核心规则**：**参数跟着它所描述的对象走同一层级** —— 转速属"这台对象"，放监测对象节点；窗长/带宽/阶次属"这个指标"，放指标节点；报警限值属"这条通道上的这个指标"，放通道节点（按指标行内联）。

## 四、改造清单

### P1 · 结构纠正（先做，你已指出）

**P1-a 额定转速上移到监测对象节点**
- 健康树「监测对象」节点新增「额定转速」输入 → 写 `monitor_object.rated_rpm`（与对象台账同一字段，单一来源）。
- 通道节点**移除**「本节点转速 + 保存转速」，改为只读一行：`生效转速 X rpm（来源：对象额定 / 批次实测 / 未设置）`。
- 数据：`monitor_object.rated_rpm` 现有 4 行全 NULL，**无需迁移**；通道节点 attrs 里无 `rpm` 残留（已核，均为 `{}`）。

**P1-b 指标参数下放到指标节点**
- `metric_assign.node_id` 语义从"通道节点 id"改为"**指标节点 id**"；参数、锁定标记、启用状态都挂指标节点。
- 健康树：**指标节点**出现「指标参数」页签（现在指标节点无可配置项）；通道节点保留**只读汇总**（该通道下各指标的生效参数摘要，不可编辑，避免两处可改）。
- 数据迁移：9 条绑定按 `(通道节点, metric_code) → 该通道下同 code 的指标节点` **1:1 映射**（树上 3 通道 × 3 指标齐全，已验证）；迁移幂等、迁移前自动备份。
- 连带改动：
  - `features/pipeline.py` 重算：按绑定行的指标节点反查父通道取数据（现在直接当通道节点用）。
  - `store/tree_template.py` 模板导入/导出：绑定落点同步改为指标节点。
  - 批量绑定（"一键绑定全部指标参数"）：遍历指标节点而非通道节点。
  - `params.py` 的优先级链不变（硬默认 < 指标定义默认 < 节点覆盖），只是"节点"从通道变指标。

### P2 · 装配不跳页（你提的原则）

1. **树上就地新建并装配**（一步完成，同一事务）
   - 监测对象：名称/类型/部位/**额定转速** → 建台账 + 装配组件节点
   - 通道：通道号（自动绑当前对象）→ 建台账 + 装配节点
   - 传感器：通道节点内表单（型号/灵敏度/量程/安装方式/标定日期）→ 建台账并挂到该通道节点；一通道一台在用，旧自动停用
2. **阈值内联**：通道节点「监测指标」页签内，每个指标行直接设 warning/alert（写 `metric_limit`）；阈值设置页保留做批量/跨通道管理。
3. **树上新建指标**：本期**不做**（按你的决定，只能选已有的 3 个内置指标）。

### P3 · 治理（体验）

4. 台账页加「已装配 / 未装配」标记与未装配清单（对象、通道、传感器）。
5. 悬空引用处理入口：节点引用的台账行被删时，给「换绑到其他台账行 / 转为自由节点」，不用删节点重建。
6. 装配唯一性从「按名字」改为**按 ref_id**（改名不再误判）；`metric_assign` 补唯一约束 `(task_id, node_id, metric_code)`（现在没有，重复行无法拦截）。

## 五、风险与取舍

| 项 | 说明 | 处理 |
|---|---|---|
| 指标节点成为参数载体 | 树模板、pipeline、批量绑定、UI 四处依赖 `node_id` 语义 | 一次性改完 + 迁移后在副本库跑全量回归；旧口径不保留双写 |
| 通道节点仍需要看参数 | 汇总视图有价值（一眼看该通道三个指标怎么配） | 只读展示，编辑入口唯一（指标节点）|
| 无唯一约束 | 迁移/批量绑定可能产生重复 | P3 加唯一约束，迁移时先去重（保留最新 id，其余软删留痕）|
| 阈值位置 | 与"参数下放"看似矛盾 | 阈值是"通道上的该指标"的业务口径，内联在通道节点更贴合使用；指标参数是算法口径，放指标节点 |

## 六、验收口径

- P1-a：对象节点能设额定转速 → 对象台账同字段变化；通道节点无输入框且显示正确来源；转速参与阶次计算的结果不变（现有测试覆盖）。
- P1-b：9 条绑定迁移后全部指向指标节点；指标节点能改参数并生效；通道节点汇总正确；重算走参数不丢；模板导出/导入闭环通过。
- P2：树上连续完成"建对象 → 建通道 → 录传感器"，全程不离开健康树；阈值内联后阈值页读到同一份数据。
- 全程：TDD（先失败测试）、`pytest` 全量 + `ruff check/format` 通过、正式库迁移前自动备份。
