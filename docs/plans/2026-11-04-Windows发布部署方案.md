# Lion-Monitor Win10 / Win11 发布部署方案（方案 A 定稿）

> 2026-11-04 · 马哥定：**便携 Python + 启动器 + Inno Setup，用户一键启动**

## 0. 一句话

安装包双击装完 → 桌面一个图标 → 双击等 15 秒 → 浏览器自动弹出工作台。用户全程不碰命令行、不装 Python、不配环境变量。

## 1. 运行时选型（关键决策，先踩过坑）

要做「一键启动 + 目录选择弹窗」，运行时必须**自带 tkinter**。这条直接排除了 python.org 的 embeddable 包：

| 候选 | 自带 pip | 自带 tkinter | 结论 |
|---|---|---|---|
| python.org `embeddable` 包 | ❌ 要手工 get-pip | **❌ 官方不含**（cpython#99566，社区公认无简洁解法） | ✗ 目录选择得另找方案 |
| **python-build-standalone**（astral-sh 维护） | ✅ | **✅ 构建产物自带 `_tkinter`**（官方 quirks 文档明确「无法从预构建产物里移除」） | ✓ **采用** |
| WinPython | ✅ | ✅ | 体积 300 MB+，太重 |
| 要求目标机预装 Python | — | — | 现场环境不可控，不稳 |

→ **采用 python-build-standalone 的 `cpython-3.11.x-x86_64-pc-windows-msvc-shared-install_only` 产物**，解压即用，含 pip + 完整标准库。

另一条收益：有了 tkinter，目录选择直接用 `tkinter.filedialog.askdirectory()`，**不再需要** WSL 那套「csc.exe 编译 C# 宿主」的链路（WSL 分支保留不动）。

社区同类做法参考：`streamlit-desktop-app`（pywebview 包成桌面窗口）—— 那样是独立窗口不依赖浏览器，但要多一层 GUI 依赖且窗口内行为与浏览器有差异，产线场景不取。

## 2. 安装目录：由用户选择（马哥 2026-11-04 要求）

### 2.1 目录页必须出现

```ini
DefaultDirName={sd}\LionMonitor     ; 默认值：系统盘下的 LionMonitor
DisableDirPage=no                       ; 必须 = no，目录选择页才会显示
UsePreviousAppDir=yes                   ; 重装/升级时记住上次选的目录
DirExistsWarning=auto                   ; 目录已存在时提示（升级场景）
```

用户可以在向导第二页**改盘、改路径**：`D:\Lion-Monitor`、`E:\产线软件\LionMonitor` 都行。

### 2.2 安装后的目录结构（跟着用户选的目录走）

```
<用户选的目录>\                  ← 例：D:\Lion-Monitor
├─ LionMonitor.exe               ← 【用户双击这个】启动器（带图标）
├─ runtime\                      ← Python 3.11 便携运行时（含 tkinter）
│  ├─ python.exe
│  ├─ Lib\site-packages\        ← 9 个依赖
│  └─ tcl\
├─ app\   src\   configs\       ← 代码（升级只换这几个）
├─ data\                         ← lion.db —— 就在安装目录里
├─ logs\                         ← lion-monitor.log
├─ backup\                       ← 升级前自动备份的 lion.db
├─ VERSION
└─ 使用说明.pdf
```

**核心约定：数据跟着程序走。** 用户把软件装在 `D:\Lion-Monitor`，数据库就是 `D:\Lion-Monitor\data\lion.db`。好处：

- 现场能直接看到、拷走、备份数据，不用去翻 `%LOCALAPPDATA%` 或注册表；
- 换电脑 = 整个目录拷过去，插上就能跑（含数据和历史）；
- 卸载时能精确地问「数据和日志要不要留」。

### 2.3 目录校验（`[Code]` 段，装之前就挡住坑）

用户能随便选，就必须当场拦住会装坏的路径。`NextButtonClick` 里逐条校验：

| 检查 | 不通过时 | 原因 |
|---|---|---|
| 不是盘根（`D:\`） | 阻止，提示换一个子目录 | 装到盘根会污染整盘，卸载容易误删 |
| 不在 `C:\Windows` / `System32` | 阻止 | 系统目录 |
| 路径长度 < 120 字符 | 阻止 | 深层目录会撞 Windows 260 字符上限（`runtime\Lib\site-packages\...` 本身就很深） |
| **写权限实测**：在目标目录试建临时文件再删 | 阻止，提示「这个目录当前账号写不进去：请换一个目录，或用管理员身份安装」 | 装完 SQLite 建不了库，是最常见的翻车点 |
| 非 ASCII（中文）路径 | **警告但不阻止**，建议改英文 | tkinter/Streamlit 一般没事，matplotlib 字体缓存偶发踩坑；现场若坚持用中文目录，允许继续 |
| 目录已存在且含旧版本文件 | 提示「检测到已有安装，本次将升级；`data\` 与 `logs\` 会保留」 | 升级场景 |

写权限探测是重点：`PrivilegesRequired=lowest`（不申请管理员）时，选 `C:\Program Files\...` 会被这条挡住并给出可操作的提示，而不是装完了打不开。

### 2.4 卸载与升级

| 场景 | 行为 |
|---|---|
| 卸载 | `[UninstallDelete]` 只删程序文件（`runtime\ app\ src\ configs\ *.exe *.dll VERSION`），**不碰** `data\ logs\ backup\`；卸载向导最后弹一次「是否一并删除数据库与日志？」默认「否」 |
| 升级安装 | `UsePreviousAppDir=yes` 自动装回原目录；安装前把 `data\lion.db` 复制到 `backup\lion_<日期>.db`；`data\` 原样保留 |
| 换目录「重装」 | 用户选了新目录 → 等于全新安装（新空库）。安装向导在检测到**别处已有旧安装**时提示一句，避免误把老数据「弄丢」（老目录里的数据仍在，只是新目录看不到） |

## 3. 一键启动流程（启动器做什么）

用户双击 `LionMonitor.exe`：

```
1. 探测 127.0.0.1:8501
   ├─ 已通 → 直接打开默认浏览器 → 退出（防重复启动，不占内存）
   └─ 未通 ↓
2. 显示「正在启动 Lion-Monitor…」（小窗口 / 托盘气泡，避免用户以为没反应反复双击）
3. 后台起服务（CREATE_NO_WINDOW，无黑窗）：
   runtime\python.exe -m streamlit run app\main.py
       --server.address 127.0.0.1
       --server.port 8501
       --server.headless true
       --server.runOnSave false
       --browser.gatherUsageStats false
4. 轮询 http://127.0.0.1:8501/_stcore/health（最多 60 s）
   ├─ 通了 → 打开默认浏览器 → 启动器退出（或最小化到托盘）
   └─ 超时/进程退出 → 弹窗显示日志末尾 20 行 + 日志路径（不是干瞪眼）
5. 端口 8501 被别的程序占用 → 从 8501 起往后探到 8510，用可用端口；全占则明确报错
```

启动器实现：**C# 单文件，用 Windows 自带 `csc.exe` 编译**（不引入任何工具链，项目里 `win_pick_folder.cs` 已是同一套路）。约 150 行：
`TcpClient` 探端口 → `Process.Start` 起服务 → `HttpClient` 轮询健康 → `Process.Start(url)` 开浏览器 → `MessageBox` 报错。

备用入口 `start.bat`（带控制台，能看到完整 traceback）只给排障用，不给用户。

**不选 PyInstaller 打启动器的原因**：又回到 bootloader 杀软误报那套，且启动器本身只有几百 KB，C# 编译零成本。

## 4. 环境与路径约定

| 项 | 值 | 说明 |
|---|---|---|
| `LION_DB` | `C:\LionMonitor\data\lion.db` | 已有环境变量支持 |
| `LION_LOG_DIR` | `C:\LionMonitor\logs` | 已有支持 |
| `LION_SCAN_DIR` | 现场实际目录，如 `D:\envision\data\四通道保存` | 已有支持，安装时由现场填 |
| `PYTHONPATH` | `C:\LionMonitor\src` | 或让 `app\store_ctx.py` 自行插入（现有逻辑已做） |
| 监听地址 | `127.0.0.1`（默认） | 只本机：无防火墙弹窗、无外网暴露 |
| Streamlit 配置 | 全部走命令行参数 | 不依赖 `%USERPROFILE%\.streamlit`，避免多用户配置污染 |

## 5. 构建流程（`scripts/build_win.ps1`）

在 Windows 构建机（或任意能跑 PowerShell 7 的机器）执行一条命令：

```powershell
pwsh scripts/build_win.ps1 -Version 0.1.0
```

内部步骤：

1. **取运行时**：下载 python-build-standalone 3.11 `install_only` 包 → 解压到 `build\stage\runtime`（首次下载后缓存，后续复用）
2. **自检 tkinter**：`runtime\python.exe -c "import tkinter, tkinter.filedialog"` —— 失败立即中止，绝不产出一个"目录选择用不了"的包
3. **装依赖**：`runtime\python.exe -m pip install -r requirements-win.txt`（9 个顶层包，Windows wheel 已实测齐全）
4. **拷代码**：`app\` `src\` `configs\`（排除 `__pycache__`、`.pyc`、测试）；建空 `data\` `logs\` `backup\`；写 `VERSION`
5. **编译启动器**：`csc.exe /target:winexe /win32icon:lion.ico launcher\LionMonitor.cs`
6. **打安装包**：`iscc installer\LionMonitor.iss /DVersion=0.1.0` → `LionMonitor-Setup-0.1.0.exe`
7. **出校验**：打印产物 SHA256 + 体积，写进 `reports/build_win_<version>.txt`

产物：**`LionMonitor-Setup-0.1.0.exe`，预计 260–300 MB**（700 MB 内容用 LZMA2 压）。

## 6. Inno Setup 脚本要点（含目录选择）

```ini
[Setup]
AppName=Lion-Monitor
AppVersion={#Version}
DefaultDirName={sd}\LionMonitor        ; 默认系统盘下；用户可以改盘改路径
DisableDirPage=no                        ; ★ 必须，否则不显示目录选择页
UsePreviousAppDir=yes                    ; 升级时记住上次的目录
PrivilegesRequired=lowest                ; 不申请管理员，普通账号可装
PrivilegesRequiredOverridesAllowed=dialog; 允许用户主动选「为所有人安装」
Compression=lzma2/ultra64
SolidCompression=yes
WizardStyle=modern
Languages: ChineseSimplified
SetupIconFile=lion.ico
UninstallDisplayIcon={app}\LionMonitor.exe
ArchitecturesAllowed=x64compatible
ArchitecturesInstallIn64BitMode=x64compatible

[Tasks]
Name: "desktopicon"; Description: "创建桌面快捷方式"; Flags: checkedonce
Name: "startup";     Description: "开机自动启动";       Flags: unchecked

[Icons]
Name: "{autodesktop}\Lion-Monitor"; Filename: "{app}\LionMonitor.exe"; Tasks: desktopicon
Name: "{autoprograms}\Lion-Monitor"; Filename: "{app}\LionMonitor.exe"
Name: "{userstartup}\Lion-Monitor";  Filename: "{app}\LionMonitor.exe"; Tasks: startup

[Run]
Filename: "{app}\LionMonitor.exe"; Description: "立即启动 Lion-Monitor"; Flags: postinstall nowait

[UninstallDelete]
; 只删程序文件，数据与日志由 [Code] 里的卸载询问决定
Type: filesandordirs; Name: "{app}\runtime"
Type: filesandordirs; Name: "{app}\app"
Type: filesandordirs; Name: "{app}\src"
Type: filesandordirs; Name: "{app}\configs"
Type: files;          Name: "{app}\LionMonitor.exe"
Type: files;          Name: "{app}\start.bat"
Type: files;          Name: "{app}\VERSION"
Type: files;          Name: "{app}\unins000.dat"
Type: files;          Name: "{app}\unins000.exe"
; 保留：data\  logs\  backup\  使用说明.pdf
```

`[Code]` 段两个钩子：

```pascal
function NextButtonClick(CurPageID: Integer): Boolean;
begin
  Result := True;
  if CurPageID <> wpSelectDir then Exit;
  Result := ValidateInstallDir(WizardDirValue);   // 见 §2.3 六条校验
end;

procedure CurUninstallStepChanged(CurUninstallStep: TUninstallStep);
begin
  if CurUninstallStep = usPostUninstall then
    if MsgBox('是否一并删除数据库与日志？' + #13#10 +
              '（选「否」保留 data\、logs\、backup\，重装可继续用）',
              mbConfirmation, MB_YESNO) = IDYES then
      DelTree(ExpandConstant('{app}\data'), True, True, True);
end;
```

**关键点**：`DisableDirPage=no` 是「允许用户选目录」的开关，漏了这一行 Inno 会直接跳过目录页、静默装到默认路径——这正是马哥要避免的。

## 7. 潜在风险与处置（按严重度）

### 高 — 会导致「装了用不了」

| # | 风险 | 触发条件 | 处置 |
|---|---|---|---|
| 1 | **数据/日志写不进去** | 装进 `Program Files`，普通账号建库失败 | 默认装 `C:\LionMonitor` + `PrivilegesRequired=lowest`；启动器启动前自检 `data\` 可写，不可写就弹窗说明 |
| 2 | **tkinter 缺失导致目录选择失效** | 误用 embeddable 包，或换运行时版本 | 构建脚本第 2 步硬性自检，失败即中止；真机验证清单第一条就是点「选择目录」 |
| 3 | **杀软/EDR 拦 python.exe 或安装包** | 企业 Defender/360/火绒 MX 策略 | ① 安装包用内部证书签名；② 提前把 `C:\LionMonitor` 加白；③ 兜底给一份 zip 绿色版（解压即用，绕开安装器拦截） |
| 4 | **8501 端口被占** | 另一套程序或上一次没退干净 | 启动器探端口 + 自动往后找；全部占用时明确提示"端口 8501–8510 都被占用" |

### 中 — 体验问题、能用但别扭

| # | 风险 | 处置 |
|---|---|---|
| 5 | **首次启动慢 10–25 s**，用户以为没反应反复双击 | 启动器显示「正在启动…」，单实例检测挡住重复；第二次双击只开浏览器 |
| 6 | **多用户登录同一台机**（RDP/换账号） | data 在安装目录，Inno 给 `Users` 组 `modify` 权限；启动器按端口判定实例，不按用户 |
| 7 | **升级后 schema 不兼容** | `VERSION` 文件 + 升级前自动备份；启动器检测版本变化时提示"已自动备份到 backup\" |
| 8 | **安装路径含中文/空格** | 默认英文路径；检测到非 ASCII 路径给红色警告，仍允许继续但不推荐 |
| 9 | **Streamlit 往 `%USERPROFILE%\.streamlit` 写配置** | 全部参数走命令行；如需固定，安装时预置一份只读 `config.toml` |

### 低 — 记录备查

| # | 风险 | 处置 |
|---|---|---|

| 12 | 浏览器兼容（IE 模式/旧 Edge） | 启动器优先用系统默认浏览器；README 注明需 Edge 79+ / Chrome |

## 11. 新增算法带来的 Python 依赖怎么处理（2026-11-04）

### 11.1 先明确三种情形

| 情形 | 谁在改 | 处理通道 |
|---|---|---|
| 内置算法（`v_RMS` / `a_Peak` / `a_RMS`）要加依赖 | 我方改项目代码 | **L2 发版**：依赖写进 `requirements-win.txt`，重打安装包 |
| 现场新增自定义指标插件，插件里 `import` 了新库 | 用户放一个 `.py` 进插件目录 | **L1 离线导入**：现场装 wheel，不重打包 |
| 临时试算 / 评估某个算法 | 同上 | L0 预装库 + L1 |

### 11.2 关键能力：便携运行时自带 pip

python-build-standalone 的 Windows 发行版**自带 pip 模块**（官方 quirks 文档：「Windows distributions have pip installed however no `Scripts/pip.exe` … because the way these executables are built」）。

所以现场可以就地装依赖，**只要用模块方式调用**：

```bat
runtime\python.exe -m pip install --no-index --find-links deps pywavelets
```

- 不需要联网构建环境、不需要管理员权限（`runtime\` 在安装目录内可写）；
- 注意不能写 `runtime\Scripts\pip.exe`，那个文件 PBS 根本不提供。

### 11.3 三级策略

**L0 · 预装「振动分析常用库」（开箱即用，覆盖大多数需求）**

| 库 | 体积 | 用途 | 建议 |
|---|---|---|---|
| scipy | 已含（96 MB） | 滤波 / FFT / 包络 | 保持 |
| numpy / pandas | 已含 | 基础 | 保持 |
| **pywavelets** | ~2.5 MB | 小波分解、小波包 | **建议预装**（性价比最高） |
| statsmodels | ~30 MB | 趋势拟合、时序 | 建议预装 |
| scikit-learn | ~40 MB | 异常检测、聚类 | 按需（L1 装） |
| numba / llvmlite | ~90 MB | JIT 加速 | 按需（L1 装） |

**L1 · 现场离线导入 wheel（主路径）**

1. 在**能联网的机器**上跑准备脚本：
   ```powershell
   pwsh scripts/fetch_wheels.ps1 -Package pywavelets -Out dep_pywt.zip
   ```
   内部就是（已实测这组参数能拿到 Windows 轮子）：
   ```bash
   pip download <包名> --only-binary=:all: --platform win_amd64 \
       --python-version 3.11 --implementation cp -d <目录>
   ```
2. 把 `dep_pywt.zip` 拷到现场机器；
3. 界面「指标配置 → 安装算法依赖」（或启动器菜单）选这个 zip / 或解压后的目录；
4. 后端执行 `runtime\python.exe -m pip install --no-index --find-links <目录> <包名>`，装进 `runtime\Lib\site-packages`；
5. 页面显示安装结果 + 当前依赖清单。

**L2 · 正式发版（唯一推荐用于长期）**

新依赖进 `requirements-win.txt` → `build_win.ps1` 重建 → 新安装包覆盖 `runtime\`。
好处：所有机器依赖一致，出问题可复现。

> **纪律建议**：正式产线只用 L2 变更依赖；L1 只用于试算评估，评估通过就把该依赖补进 `requirements-win.txt` 随下个版本发。

### 11.4 插件侧：声明依赖 + 缺库时给人话提示

插件模板新增选填项：

```python
REQUIRES = ["pywavelets>=1.4"]     # 选填：运行时需要的第三方库
```

`metric_plugins._load_one()` 增加一步：加载后逐个 `importlib.util.find_spec(name)` 检查，
缺失时不抛 `ModuleNotFoundError` 堆栈，而是抛可读的 `PluginError`：

```
该算法需要 pywavelets，当前环境未安装 → 请到「指标配置 → 安装算法依赖」导入 wheel 包
```

页面把这个原因显示在算法列表里（现在是「导入失败：ModuleNotFoundError: No module named 'pywavelets'」，用户看不懂该怎么修）。

### 11.5 一致性风险与处置

| 风险 | 后果 | 处置 |
|---|---|---|
| 多台机器各自 L1 装依赖，版本不同 | 同一份数据算出不同值，难排查 | `runtime\deps.lock` 存 `pip freeze` 快照；页面「关于」显示依赖清单 + 版本 |
| 算法依赖升级后历史值未重算 | 新旧值混在一条曲线上 | 沿用现有 stale 机制：依赖版本变化写进 `VERSION`，启动器提示「算法环境已变更，建议重算」 |
| 现场装了与环境不匹配的 wheel（如 cp312 / 32 位） | pip 报错看不懂 | 导入前校验文件名含 `cp311` + `win_amd64`/`any`，不匹配直接给人话提示 |

### 12.2 连带冲突一：目录选择弹窗在「服务端屏幕」

**问题**：现在的「📁 浏览目录」是服务端弹窗（`win_picker` → `wscript` 拉起 FolderBrowserDialog），
窗口出现在**跑服务那台机器**的桌面上。单机用没问题，但马哥要的两个场景直接冲突：

- **局域网多人访问**：同事在自己电脑点「浏览目录」，弹窗跑到主机屏幕上，他自己啥也看不到，页面一直转圈；
- **开机自启（服务模式）**：Windows 服务跑在 session 0，**没有交互桌面，弹窗永远不可见**，等于该功能彻底失效。

**建议改法（推荐）**：把「浏览目录」改成**网页端目录浏览器**
- 服务端提供"列目录"能力（`os.scandir`），页面用树/面包屑浏览服务器的磁盘；
- 任何浏览器都能用，不依赖桌面会话，服务模式也正常；
- 顺带摆脱 `wscript`/`csc`/`/mnt/c` 那一整套历史包袱。

保留：WSL 开发时仍走原生弹窗（现有分支不动），Windows 部署走网页端。

工作量：列目录接口 + 面包屑/上下级导航 + 新建文件夹 + 「用这个目录」→ 约 4~6 小时。

> 若马哥坚持用系统原生弹窗，那就只能「单人本机用 + 不开服务自启」，与第 2、3 条决定互斥。

### 12.3 连带冲突二：防火墙规则需要管理员权限

放行 8501 要给 Windows 防火墙加规则（`netsh advfirewall firewall add rule`），**必须提权**。

→ 安装器改为 `PrivilegesRequired=admin`（装一次，之后用户日常不需要管理员）：

```ini
PrivilegesRequired=admin
[Run]
Filename: "netsh.exe"; Parameters: "advfirewall firewall add rule name=""Lion-Monitor 8501"" dir=in action=allow protocol=TCP localport=8501 profile=private"; Flags: runhidden
```

同时给数据目录授权普通用户可写（否则以管理员装的库文件，普通账号启动后写不进 `data\`）：

```ini
[Dirs]
Name: "{app}\data";   Permissions: users-modify
Name: "{app}\logs";   Permissions: users-modify
Name: "{app}\backup"; Permissions: users-modify
```

防火墙只放行 **private**（专用网络），不给公用网络开口子。

### 12.4 连带冲突三：开机自启必须是「无人登录也跑」

`{userstartup}` 快捷方式只在**该用户登录后**启动。主机重启卡在登录界面时，同事就访问不到。

**采用 Windows 服务（NSSM，随包 ~300 KB）**：

```bat
nssm install LionMonitor "C:\LionMonitor\runtime\python.exe" ^
    "-m streamlit run C:\LionMonitor\app\main.py --server.address 0.0.0.0 --server.port 8501 --server.headless true"
nssm set LionMonitor AppDirectory "C:\LionMonitor"
nssm set LionMonitor Start SERVICE_AUTO_START
nssm set LionMonitor AppExit Default Restart
nssm set LionMonitor AppStdout "C:\LionMonitor\logs\service.log"
nssm set LionMonitor AppStderr "C:\LionMonitor\logs\service.err.log"
```

- 开机即起，不依赖任何用户登录；
- 崩溃自动重启（`AppExit Default Restart`）；
- 服务跑在 SYSTEM / 指定账户，**没有交互桌面** —— 再次印证 §12.2 必须改网页端目录选择。

服务模式与「启动器双击」并存：双击 `LionMonitor.exe` 时若检测到服务已在跑，就只打开浏览器（访问 `http://<主机IP>:8501`）。

## 16. Windows Server 2022 Standard / Win10 / Win11 三平台兼容（马哥 2026-11-05）

### 16.1 差异与影响评估

| 项 | Win10 / Win11 | Server 2022 Standard | 对本软件的影响 |
|---|---|---|---|
| **浏览器** | 自带 Edge（Chromium） | **默认只有 IE11，Edge 需额外安装** | ⚠ **最高风险**：Streamlit 不支持 IE，没有 Edge/Chrome 就完全打不开界面 |

### 16.2 处置动作（写进阶段 2）

1. **自检必查浏览器**：`tools\selfcheck.py` 增加一项 —— 依次找
   `msedge.exe` / `chrome.exe`（注册表 `App Paths` + `C:\Program Files (x86)\Microsoft\Edge\Application\` 等常见路径）。
   找不到就明确提示「本机没有 Edge/Chrome，Streamlit 界面需要现代浏览器，
   Server 2022 请先安装 Microsoft Edge」。
2. **启动器优先 Edge**：`LionMonitor.exe` 打开浏览器时，先试 Edge、再试 Chrome、最后才用系统默认
   （避免在 Server 2022 上默认落到 IE11）。

## 17. 日志落盘（马哥 2026-11-05：「报错信息都会报错到 log 吧，方便日后运营」）

### 17.1 实测发现的三个漏洞

| # | 漏洞 | 证据 | 影响 |
|---|---|---|---|
| 1 | **直接访问页面 URL 时日志根本不初始化** | 用 `/ingest` 打开，`logs/lion-monitor.log` 一直是旧内容；在 `setup_logging` 里写 trace 文件，trace 为空 | 现场从导航点进任何页面，日志全丢；只有走首页启动那一次才有日志 |
| 2 | **Streamlit 内部异常不落我们的文件** | 造一个 `raise RuntimeError` 的页面：终端有 `Uncaught app execution` + traceback，日志文件 0 字节 | 真正让页面崩掉的 bug 没记录 |
| 3 | **业务错误只显示不记录** | 40 个 `except` 块里只有 1 处调 logger | 导入失败、目录不可用、计算失败等运营要查的事，只能靠用户口述 |

### 17.2 根因

- Streamlit 1.66（uvicorn/starlette 架构）多页模式下，**深链接到 `/xxx` 只执行 `pages/xxx.py`，不执行 `app/main.py`** → `main.py` 里的 `setup_logging()` 被跳过。这是漏洞 1 的根因，也是最隐蔽的一个。
- Streamlit 在 `streamlit/logger.py` 里给**每个模块级 logger** 单独 `addHandler(stderr)` 且 `propagate=False`（实测 60+ 个，含 `streamlit.runtime.scriptrunner.script_runner`）→ 只改父 logger 拦不住子 logger。这是漏洞 2 的根因。

### 17.3 修法（三层，缺一层就有盲区）

1. **初始化位置**：`setup_logging()` 从「只挂在 `main.py`」改成**同时挂在 `app/ui.py`**（每个页面都 import ui）。任何入口进来日志都初始化；`main.py` 的调用保留（幂等，不重复挂 handler）。
2. **接管 Streamlit logger**：`_take_over_streamlit_loggers()` 遍历 `logging.Logger.manager.loggerDict` 里所有 `streamlit*` logger，摘掉自带 stderr handler、`propagate=True`，并把级别放开到我们的级别。
3. **业务错误统一记录**：
   - `ui.flash(tone="error"/"warning")` 自动记一条（success 不记，免得淹没真错误）
   - 新增 `ui.error()` / `ui.warning()`（显示 + 记 ERROR/WARNING），10 个页面里 34 处 `st.error` + 22 处 `st.warning` 全部换过来
   - `main.py` 用 `try/except` 包住 `st.navigation(...).run()`，先 `_LOGGER.exception` 再原样抛出（记录不影响页面照常显示报错框）
4. **自己的 logger 直接挂 handler**：`_attach_own_handlers()` 给 `lion_monitor.*` 直接挂文件 + 控制台 handler 并 `propagate=False`，不依赖 root 是否被重置。

### 17.4 实测结果

| 场景 | 修前 | 修后 |
|---|---|---|
| 打开 `/ingest` 后查日志 | 文件不更新（trace 为空） | `数据库初始化/迁移开始` 等正常写入 |
| 点「扫描目录」输入不存在的路径 | 页面有警告，日志无 | `2026-11-05 11:47:32 WARNING lion_monitor.ui: 界面警告: 目录不存在：/tmp/不存在的目录_test` |
| 页面未捕获异常 | 只在终端 | 日志含 `Uncaught app execution` + 完整 traceback（12 行） |

测试：`tests/test_logging_coverage.py`（5 例）—— 未捕获异常落盘、flash 的 error/warning 落盘且 success 不落盘、`ui.error` 为 ERROR 级、streamlit 子 logger 被接管、业务 logger 与主日志同一个文件。

### 17.5 现场运维怎么查日志

| 项 | 值 |
|---|---|
| 位置 | `<安装目录>\logs\lion-monitor.log`（WSL 开发时是项目根 `logs/`） |
| 轮转 | 单文件 10 MB × 5 个（`lion-monitor.log.1` … `.5`），最多约 50 MB |
| 格式 | `2026-11-05 11:47:32 WARNING lion_monitor.ui: 界面警告: …`（时间 + 级别 + 模块 + 内容） |
| 找报错 | `Select-String -Path logs\lion-monitor.log -Pattern "ERROR|界面报错|Uncaught"` |
| 换目录 | 环境变量 `LION_LOG_DIR` 可整体改到别处（阶段 2 的自检脚本会用） |
| 启动器失败 | 弹窗显示日志末尾 20 行；同时整份日志留在 `logs\`，不会只留在弹窗里 |

> 原则：**页面上用户看得到的错误，日志里必须有同一句话**；页面上看不到的异常（未捕获），日志里必须有 traceback。

### 18.3 为什么启动器和 .iss 只能静态验证

WSL 里没有 `csc.exe` 也没有 `ISCC.exe`，真实编译只能在 Windows 上做。为了不让「编不过」的代码进仓库，用 `tests/test_installer_assets.py`（31 例）钉死这些决定：

- **C# 5 语法红线**：`csc.exe v4.0.30319` 只认 C# 5，测试扫描 `$"`、`nameof(`、`?.`、`out var`、`is not`、`record`、表达式体成员 —— 出现就红（注释已剥离，不会误报）
- **局域网**：启动器必须有 `--server.address 0.0.0.0`，不许出现 `127.0.0.1`
- **Server 2022 无 IE**：必须含 `msedge.exe` 且排在 `chrome.exe` 前面
- **目录可选**：`.iss` 必须有 `DisableDirPage=no` + `DefaultDirName={sd}\LionMonitor`
- **卸载保数据**：`[UninstallDelete]` 里不许出现 `data` / `logs` / `backup`
- **规则名一致**：`.iss` 与 `selfcheck.py` 的防火墙规则名必须都是 `Lion-Monitor 8501`
- **构建脚本完整性**：PBS / requirements / csc / nssm / ISCC / deps.lock / selfcheck 七步齐全，且有退出码检查

### 18.4 无 GitHub 网络的处置（2026-11-05 实测）

构建机（马哥的 Server 2022）实测：

| 源 | 结果 |
|---|---|
| `api.github.com` / `github.com` | ❌ **完全不通**（HTTP 000，立即失败） |
| `python.org` / `registry.npmmirror.com` | ✅ 通（镜像 0.4s，官方 2.1s） |
| `pypi.org` / `pypi.tuna.tsinghua.edu.cn` | ✅ 通 |
| `nssm.cc` | ✅ 通 |

python-build-standalone 只在 GitHub 发布 → **PBS 这条路在你们网络上走不通**。处置：

1. **运行时改用官方 embeddable**（`python-3.11.9-embed-amd64.zip`，11 MB）。
   之前选 PBS 的唯一理由是它自带 tkinter，而 embeddable 没有 —— 但本项目**根本不用 tkinter**：
   - 界面是网页版（Streamlit）
   - matplotlib 直接用 `FigureCanvasAgg`（不是 TkAgg）
   - 目录选择已改网页端（不再弹原生窗口）
   所以 embeddable 完全够用，体积还小了 40 MB。
   embeddable 要补两处：`python311._pth` 加 `Lib\site-packages` + `import site`；再用 `get-pip.py` 装 pip。
2. 构建脚本改为**三级回退**：`-RuntimeArchive` 本地包 → PBS（GitHub 通时）→ embeddable（镜像/官方）。
3. 依赖改成**离线 wheel 安装**：`wheels\` 里有 60 个 win_amd64 轮子（209 MB）时，
   自动加 `--no-index --find-links wheels`，全程不联网。
