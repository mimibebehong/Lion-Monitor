# 指标参数体系与频率参数设计

> 起草：2026-10-31　｜　适用：Lion-Monitor　｜　状态：待马哥确认后实施
> 背景：健康树节点上配置指标时，不同监测对象、不同指标需要各自的详细参数（特征频率、计算时长、分析带宽等），当前 `metric_def.params_json` / `metric_assign.params_json` 字段存在但计算层未使用，`VELOCITY_BAND` 仍硬编码。

---

## 1. 目标与非目标

**目标**

1. 节点配置指标时，该指标的全部参数都可见、可改（含带宽类）。
2. 参数项随指标定义变化——选不同指标，表单字段自动换。
3. 带宽类参数正常走默认值，改过的才显眼。
4. 频率参数两级管理：监测对象台账 + 节点手填覆盖。
5. 参数改动可追溯到具体指标值。

**非目标（本期不做）**

- 不做多用户权限、不做参数版本回滚 UI。
- 不做自动寻优/自适应带宽（后续可加）。

## 2. 数据模型改动

### 2.1 指标定义：声明参数 schema 与默认值

```sql
ALTER TABLE metric_def ADD COLUMN params_schema_json TEXT DEFAULT '[]';  -- 字段声明
ALTER TABLE metric_def ADD COLUMN params_default_json TEXT DEFAULT '{}'; -- 默认值
```

`params_schema_json` 示例（v_RMS）：

```json
[
  {"key":"window_s","label":"计算时长","group":"basic","type":"float","unit":"s","default":2.0,"min":0.05,"help":"单个计算点所用原始数据长度（马哥定 2 s）"},
  {"key":"step_s","label":"计算步长","group":"basic","type":"float","unit":"s","default":2.0,"min":0.05,"help":"默认与时长相同=不重叠；末段不足一窗丢弃"},
  {"key":"band_low","label":"带通下限","group":"advanced","type":"float","unit":"Hz","default":10,"min":2,"help":"硬下限 2 Hz（Q9）；窗长装不下 10 个周期时自动抬高并提示"},
  {"key":"band_high","label":"带通上限","group":"advanced","type":"float","unit":"Hz","default":1000,"help":"默认 10–1000 Hz（马哥定）"},
  {"key":"window_fn","label":"窗函数","group":"advanced","type":"enum","options":["hanning","hamming","blackman","kaiser","rect"],"default":"hanning"},
  {"key":"detrend","label":"去直流","group":"advanced","type":"bool","default":true}
]
```

- `group=basic` → 常改，默认展开；`group=advanced` → 带宽/算法类，默认折叠，显示"默认值"。
- `type` 决定控件：float/int/bool/enum/order。
- 新增指标只需在定义里加 schema，UI 自动适配，不改前端代码。

### 2.2 节点绑定：只存覆盖项

```sql
-- metric_assign.params_json 语义改为「覆盖项」，只存与生效默认值不同的字段
ALTER TABLE metric_assign ADD COLUMN params_locked INTEGER DEFAULT 0;  -- 1=固化全部参数，不再跟随定义
```

存储示例：

```json
{"band_high": 2000}            // 只覆盖了一项，其余仍跟随定义
```

`params_locked=1` 表示"固化全部参数"：把当时的全部生效值写入 `params_json`，此后定义改默认值不影响本节点。

### 2.3 指标值：参数快照

```sql
ALTER TABLE metric_value ADD COLUMN node_id INTEGER;    -- 方案 A 追加：值按节点存（指向健康树通道节点，历史行留空）
ALTER TABLE metric_value ADD COLUMN params_hash TEXT;   -- sha1(指标码 + fs + 夹紧后生效参数) 前 12 位（P5-1 / S6）
ALTER TABLE metric_value ADD COLUMN effective_params_json TEXT;  -- 夹紧后实际生效参数快照，历史行为空（P5-1 / S6）
ALTER TABLE metric_value ADD COLUMN rpm_used REAL;      -- 本次计算所用转速
ALTER TABLE metric_value ADD COLUMN rpm_source TEXT;    -- measured | rated
ALTER TABLE metric_value ADD COLUMN stale INTEGER DEFAULT 0;
```

`params_hash` 用**夹紧后**的生效参数：带通上限越界时被夹到 `fs/2 × 0.95`
（与 `_band_filter` 同一口径），所以 `band_high=16000` 与 `30000` 在 fs=32000 下指纹相同；
采样率或指标码不同则指纹不同。

参数或转速基准变化后，旧值置 `stale=1`，用户手动重算后覆盖为新值。

> **口径已于 S4A（2026-11-02）修订**：原写「重算生成新行，不覆盖历史」，现按任务书改为
> 「同一 `(node, code, computed_at)` 直接覆盖为新值并置 `stale=0`」（与导入同一点位覆盖一致），
> 当前参数下不再产生的旧点位软删留痕。理由与实测见 §17。

### 2.4 频率参数：挂在监测对象上，归一化存储

> **字段口径已于 CF-1（2026-11-02）按任务书定稿**：原草案的 `part / kind / name / hz_fixed`
> 换成附件口径的 `part_code / part_name / part_type / component_kind / freq_kind / value_hz`，
> 并补 `channel_code`（多值）、`geom_d`、`note`。下表是**实际落库**结构。

```sql
CREATE TABLE component_freq (
  id            INTEGER PRIMARY KEY,
  task_id       INTEGER NOT NULL,
  object_id     INTEGER NOT NULL,          -- monitor_object.id（监测对象台账）
  part_code     VARCHAR(64),               -- 监测部件编号（如 Z1_R / 4D）
  part_name     VARCHAR(128),              -- 监测部件名称
  part_type     VARCHAR(32),               -- 附件口径：齿轮 / 轴承 / 行星齿轮 / 轴
  channel_code  VARCHAR(255),              -- 逗号分隔多值（Chan_1,Chan_8），一部件可挂多通道
  component_kind VARCHAR(16),              -- gear | bearing | planet | shaft | other
  ref_rpm       REAL,                      -- 录入时参考转速（附件由 OM1×60 反推）
  hz_at_1rpm    REAL,                      -- 归一化值（= value_hz / ref_rpm，等价阶次 ÷ 60）
  scaling       VARCHAR(8) NOT NULL,       -- speed | fixed
  freq_kind     VARCHAR(16),               -- om1|om2|omx|om2x|bpfi|bpfo|ftf|bsf
  value_hz      REAL,                      -- 录入原始频率值（留痕；导出按它原样输出）
  geom_d        REAL,                      -- 附件 D 列（几何尺寸）
  note          TEXT,
  created_at    DATETIME,
  updated_at    DATETIME,
  deleted_at    DATETIME
);
CREATE UNIQUE INDEX uq_component_freq_active
  ON component_freq (object_id, part_code, freq_kind)
  WHERE deleted_at IS NULL;
```

**归一化口径**：`hz_at_1rpm = 参考转速下的频率 ÷ 参考转速`，等价于"阶次 ÷ 60"。
界面上按你熟悉的"在 1500 rpm 下的 89.6 Hz"录入，入库自动换算成 `0.0597`；也可直接输阶次 `3.05×`。

**通道显示名**不另建表：导入附件时把「振动通道名称」写进 `channel_reg.remark`，
`channel_code` 多值负责"哪些通道监测这个部件"。同部件跨通道只有一条频率记录。

**必须区分两类**（否则峰值位置会错）：

| scaling | 例子 | 运行期 |
|---|---|---|
| `speed` | BPFO/BPFI/BSF/FTF、GMF、转子条通过 | `f = hz_at_1rpm × rpm_actual` |
| `fixed` | 2×线频（50 Hz→100 Hz）、共振/固有频率 | `f = hz_fixed`，与转速无关 |

### 2.6 频率选择带宽（容差带）

判据/选峰用的"目标频率左右带宽"，属于 `markers`，不进 `params`（改它不重算指标值，只重画标记与判据）。

```json
"markers": {
  "f0_hz": 145.0,
  "bands": {
    "mode": "percent_abs",        // 百分比 + 低频绝对值
    "pct": 3.0,                   // 常规：±3%
    "min_hz": 1.0,                // 低频：±1 Hz
    "low_cut_hz": 50.0            // 分界：f < 50 Hz 走绝对值
  }
}
```

**取带宽规则（默认值，逐项可改）**

```
f < low_cut_hz(50)  →  Δ = min_hz = 1 Hz
f ≥ low_cut_hz(50)  →  Δ = pct × f = 3% × f
下限保护：Δ ≥ 2 × 频率分辨率（Δf = fs / N），否则窗口不满 2 个 bin 会漏峰
```

- 该带宽**统一用于三处**：①选主峰（peak picking）②判断目标频率处是否存在显著峰 ③绘图时标记线左右的范围带，三处口径必须一致
- **包络谱单独一套**：`env_bands` 默认 `pct=5%`（解调误差比直接谱大），低频分界与绝对值同普通谱（f<50 Hz → ±1 Hz）
- 带宽、百分比、分界频率均为可改参数，默认值来自指标定义

> **分辨率校验（与默认时长强相关）**：默认计算时长 2 s、采样率 fs → 分辨率 Δf = fs/(fs×2) = **0.5 Hz**，`2×Δf = 1 Hz`，正好等于低频绝对值带宽，保护不触发但已到临界。
> 若日后把时长改到 1 s，Δf 变 1 Hz、保护下限升到 2 Hz，**±1 Hz 的窗口会被自动放大到 ±2 Hz**——界面需提示"已按分辨率下限保护"。

## 3. 参数继承与优先级

### 3.1 生效参数 = 逐层合并

```
系统硬默认（代码 PARAM_DEFAULTS）
  <  指标定义默认（metric_def.params_default_json）
  <  节点覆盖（metric_assign.params_json，仅当 params_locked=0）
  <  固化值（params_locked=1 时该 JSON 即全量生效值）
```

### 3.2 转速优先级（无全局默认转速）

```
节点手填 rpm  >  批次实测转速（工频/编码器）  >  监测对象 rated_rpm
```

**不设全局默认转速**（马哥 2026-10-31 定）：拿不到转速时**不猜**，直接限制可用指标范围（见 3.3）。

- 结果写入 `metric_value.rpm_source`：`measured` / `node` / `rated`，界面与报告标注来源
- 转速缺失时，任何需要转速的指标**不出现在可选列表里**，而不是给个 1500 蒙一个

### 3.3 指标可用性门控（转速依赖矩阵）

| 指标类别 | 代表指标 | 依赖 | 无转速时 |
|---|---|---|---|
| 时域类 | a_Peak、a_RMS、峰峰值、峭度、偏度、波形因子、脉冲因子、直流偏置 | 只需采样率 | ✅ 可选 |
| 频域绝对值类 | v_RMS（10–1000 Hz 带通）、主峰频率、谱质心、频带能量占比 | 只需采样率 | ✅ 可选 |
| 阶次/特征频率类 | 1×、2×、BPFO/BPFI/BSF/FTF、GMF、边带、包络谱特征频率 | 需要转速 | ❌ 不可选，置灰并提示"需先在监测对象或本节点设置转速" |

门控规则：

```
节点生效转速 = 节点手填 ?? 批次实测 ?? 监测对象 rated_rpm
若为 None → 指标的 markers 里存在 scaling=speed 的频率项时，该指标禁用
```

- 界面：指标下拉中禁用的项灰显，悬浮提示原因；已绑定的指标若转速被清空，标红提示"缺少转速，无法计算"
- 批次实测转速到达后，之前被禁用的指标自动可算

### 3.4 频率参数优先级

```
节点手填（markers 里显式值）  >  监测对象 component_freq 派生值  >  未配置（灰显提示）
```

节点手填与对象派生值相差 >5% 时提示"可能选错型号"，仅提示不阻断。

## 4. 界面交互

### 4.1 节点配置指标的完整流程

```
健康树选中节点 → 指标页签 → 点「添加指标」→ 选指标（v_RMS…）
   ↓
表单按该指标 params_schema 动态渲染
   ├─ 基本参数（展开）：计算时长、步长
   └─ 高级参数（折叠）：带通下限/上限、窗函数、去直流  ← 显示「默认值」
   ↓
来源标注：每项右侧灰字「默认」「来自定义」「本节点已覆盖」
   ↓
校验：band_high ≤ fs/2；window_s ≥ 10 / band_low；step_s ≤ window_s
带通下限（Q9）：硬下限 2 Hz（低于它保存直接拒绝）；窗长装不下 10 个周期时
自动抬到 10 / window_s 并提示「已按窗长自动抬高到 X Hz」
   ↓
保存 → 只把改动项写入 params_json
```

### 4.2 带宽类参数的处理

- 默认折叠，标题写「高级参数（带宽/算法）· 使用默认值」。
- 改动任意一项后，折叠标题变「高级参数 · 已修改 2 项」，并有橙色角标。
- 提供「恢复默认」按钮（清空该项覆盖）。
- 带宽参数改动 → 标记受影响的通道数据集数量，保存时提示"将影响 N 个数据集，需重算"。

### 4.3 频率参数配置

监测对象页新增「频率参数」页签：

```
对象：3#辊压机
部件：驱动端轴承   类型：轴承
参考转速：1500 rpm（预填自对象 rated_rpm，可改）
频率项：
  BPFO   [ 89.6 ] Hz @1500rpm  → 3.05×   scaling: speed
  BPFI   [ 135.2] Hz @1500rpm  → 4.60×   scaling: speed
  2×线频 [ 100.0] Hz（固定）              scaling: fixed
```

节点配置指标时，频率字段旁有来源下拉：「跟随对象」/「手动覆盖」；跟随对象时显示"来自 3#辊压机 驱动端轴承，按 1480 rpm 算得 88.4 Hz"。

def compute_metrics(samples, sample_rate, params=None, codes=None) -> dict[str, float]:

### 17.2 与设计 / 需求不一致、须知晓之处

1. **旧值覆盖而非新行**（§2.3 原口径）：见 §2.3 的修订说明与 §17.4-1 的理由。
2. **作废旧点位是软删**：窗长 / 步长改了以后旧时间点在当前参数下不再存在，不软删就会永远挂在
   「待重算」上；软删留痕（回收站逻辑不涉及指标值行），完成提示里报作废条数。
3. **导入判无效的文件不重算**：与「判无效通道不落值」同口径，重算不凭空造值。
4. **重算区间是全历史批次**（不是趋势页 30 天窗）：保证「待重算 N 条」能清到 0；30 天只影响显示。
5. **预计耗时是经验系数**（每文件 0.1 s + 每点 0.02 s，最少 1 s），只做提示；实测 2 文件 8 点提示
   「约 1 秒」，实际 1 秒量级完成。
