# Windows 部署提速调研（2026-11-05）

> 背景：马哥反馈「好慢啊」，要求从 GitHub 上调研是否有更省事/更快的 Windows 部署经验。
> 结论先行：**不改架构，改三处工具链**。

## 一、先分清「慢」在哪

| 环节 | 现状 | 频率 | 是否值得优化 |
|---|---|---|---|
| 首次构建：准备运行时 + 装 60 个包（900MB） | 10–15 分钟 | **一次性**（每台机器一次） | 值得（uv 可砍到 1–2 分钟） |
| 打包成安装器（Inno LZMA2/ultra64） | 5–10 分钟 | 每次发布 | 值得（降压缩档或改绿色版） |
| 安装到目标机（解压 900MB） | 2–4 分钟 | 每台机器一次 | 值得（绿 zstd/7z 解压快 2–10 倍） |
| **改完 UI 后重新发布** | 拷 2.5MB 代码 | **每天都做** | **已经很快**（`--skip-runtime --skip-deps`，秒级） |

关键判断：本项目架构已定稿为「**一台服务器装、局域网其他人用浏览器访问**」，
所以 900MB 只装一次。真正天天重复的是「改代码→看效果」，那条路本来就只需秒级。
**优化重点应放在：首次构建 + 安装包体积/解压速度。**

## 二、四条技术路线（含社区实测数据）

### A. 优化现有方案（便携 Python + 启动器 + Inno）—— 推荐

| 改进项 | 依据 | 预期收益 |
|---|---|---|
| pip → **uv** 装依赖 | Streamlit 官方 2024 年把 Community Cloud 从 pip 换 uv，**部署时间缩短 55%**；uv 官方基准「比 pip 快 8–10 倍」，差距主要来自并行下载/解压 + 全局缓存（pip 自 2013 年就有「并行下载」的未解决 issue） | 装 60 包：10 分钟 → **1–2 分钟**（离线 wheel 场景收益略低于联网，但解压并行仍然显著） |
| Inno 压缩档降档 | inno/NSIS 社区实测：`lzma2/ultra64` 换 `lzma2/max` 或 `zstd`，**解压快 2–10 倍**，体积增 15–30% | 安装耗时：2–4 分钟 → **40–70 秒** |
| 新增「**绿色版**」发布通道 | 工业现场常见做法：不装软件，解压即用 | 省掉整个 Inno 流程（压缩 5–10 分钟 + 安装 3 分钟），现场拷 250MB zip → 解压 → 双击 exe |

绿色版细节：`dist\` 打成 `LionMonitor-0.1.0-portable.7z`（预计 240–280MB），
内含 README 说明「解压到 D 盘任意英文/中文目录，双击 LionMonitor.exe」。
数据仍在解压出来的 `data\` 目录，跟程序走。

### B. PyInstaller（onedir）—— 不适合本项目

- 优点：单一工具链，产物自带解释器，用户看到的就是一个 exe。
- 致命点：**每次改 UI 都要重打包，一次 10–20 分钟**。本项目界面迭代极其频繁（马哥几乎每天调 UI），
  迭代成本会远高于现在的「拷 2.5MB 代码」。
- 另需适配：13 处 `st.Page` 字符串路由、Streamlit 24MB static 资源、plugin 动态加载、`__file__` 定位资产。
  这些在便携方案里本来就成立，改 PyInstaller 反而要重新踩一遍。

### C. Nuitka（编译成 C）—— 不适合

- 优点：启动快 2–5 秒级，代码保护。
- 致命点：**编译 30–60 分钟**，Windows 上还要 MSVC 工具链 + 数 GB 磁盘。
  对「一天改十次界面」的场景完全不成立。
- 社区共识（2026 多篇基准）：Nuitka 的构建时间是 CI/CD 成本，只适合发版频率低的商业产品。

### D. stlite（Streamlit → WASM，纯浏览器）—— 不可行

- 优点：体积小（~50MB）、零安装、双击就跑。
- 致命点：**Pyodide/WASM 环境里没有 numba、PyWavelets、statsmodels 的原生扩展**。
  本项目 4 个扩展算法依赖全废，滤波（pywt）、频谱校正（statsmodels）、
  加速计算（numba）都用不了 → 指标算不出来。

## 三、推荐动作（按性价比排序）

1. **【立刻，零风险】先跑 `build.bat --skip-runtime --skip-deps`**
   依赖已装好（949MB dist 已在），这一步只做：拷代码 + NSSM + csc 编译 + 自检 + 打包，
   预计 1–2 分钟就能拿到 `dist\LionMonitor.exe`，之后 dist 目录本身就是可直接运行的程序。

2. **【半小时】加绿色版通道**
   `build.py` 增加 `--portable` 参数：dist 完成后调 7z 打包成 `LionMonitor-<版本>-portable.7z`
   + 生成 `解压后先看我.txt`。现场不用装，解压即用。

3. **【半小时】uv 加速依赖安装**
   `build.py` 检测 `uv.exe`（随构建机预置 `.build\uv.exe`，约 30MB），有则用
   `uv pip install --python dist\runtime\python.exe --no-index --find-links wheels -r requirements-win.txt`，
   没有则回退 pip。预计装依赖从 10 分钟降到 1–2 分钟。

4. **【十分钟】Inno 压缩档降级**
   `Compression=lzma2/ultra64` → `lzma2/max`，`SolidCompression=yes`。
   体积 +15%，安装快一倍以上。
