## 一、需求还原

```
① 建立测试任务
   ↓
② 配置监测对象（设备/工位，含额定转速）
   ↓
③ 测试传感器（通道、型号、灵敏度、量程、安装方式）
   ↓
④ 配置特征指标及参数（算什么、按什么参数算）
   ↓
⑤ 加载已采集振动数据（一次采集=多通道多文件） → ⑥ 数据有效性判断
   ↓
⑦ 指标计算（按阈值配置判定 ok/warn/alert）
   ↓
⑧ 特征指标历史趋势查看（逐点，不聚合）
   ↓
⑨ 数据集管理（查询 / 软删除，删除时指标同步不可见 / 回收站恢复）
   ↓
⑩ 通道级分析任务：绘图任务、FFT 任务、包络谱任务
```

两条硬性语义：

- **删除必须级联到指标**：删数据集 → 其下通道 → 通道下指标值、绘图任务、分析任务，全部同步进入删除态，不允许残留孤儿数据。
- **通道是一等公民**：绘图/FFT/包络谱任务挂在通道上；通道粒度 = 一个源文件（当前格式一个文件一个通道）。

## 五、读取层抽象（决策 1 落地）

本期只支持 envis `.dat`，但接口按"多格式可插拔"设计，后续加 CSV/MAT 不动调用方。

```python
class DataReader(Protocol):
    format_key: str                              # "envis_dat"
    def sniff(self, path: Path) -> bool: ...     # 扩展名 + 文件头特征
    def read_header(self, path: Path) -> FileMeta: ...
    def read(self, path: Path) -> VibrationRecord: ...
```

| 组成 | 说明 |
|---|---|
| `FileMeta` | 通道码、采样率、点数、起始时间、站点、设备 IP、格式版本、缩放系数（与现有 `VibrationMeta` 对齐） |
| 注册表 | `READERS = {"envis_dat": EnvisDatReader}`，`resolve(path)` 按顺序 sniff 命中 |
| 现有代码复用 | 已实现的 `lion_monitor/ingest/vibration.py` 包装成 `EnvisDatReader`，内部逻辑不改 |
| 扩展位 | CSV/MAT 各自实现一个 Reader 并注册，导入页无需改动 |
| 本期不做的 | 不做"任意未知格式自动猜测"，不做格式转换器 |

现状说明：`read_vibration` 已按"长度必须 = 512 + 4N"校验，属于**结构级**检查，保留在 Reader 内部。

**样本单位口径（v5 确定，2026-10-30）**

- 振动文件的工程单位**以文件头 `scale`（偏移 0x08，float32）为准**：
  `工程值 = 文件内 float32 原始值 × scale`，由 `read_vibration` 统一乘好后返回。
- 当前现场 `envis .dat` 的 `scale = 1.0`，文件内值本身已是加速度 **g**；
  实测印证：CH2 峰值 0.8294 g、波峰因数 1.43（≈√2，近似正弦 145 Hz），
  按 g 计算 `v_RMS ≈ 6.2~6.4 mm/s`，与库中 6.231 mm/s 一致；
  若误当 mV 处理会得到 0.013 mm/s（差 500 倍），物理上不成立（CH1 将低至 16 µg，低于传感器噪声底）。
- 文件头**不含灵敏度字段**，`sensor.sensitivity_mv_per_g`（如 500 mV/g）只作台账与追溯，
  **不参与**计算链路换算。

## 六、数据模型

### 6.1 实体关系

```
test_task (测试任务)
   │ 1
   ├──────── n task_node (健康树节点，v3 新增)
   │              node_type: device → component → channel → metric → threshold
   │              设备（辊压机1/分切机2）与监测对象（轴承/齿轮/电机）都由节点承载
   │
   ├──────── n dataset (数据集 = 一次采集批次) 1 ── n channel (通道 = 一个源文件)
   │                                                  │
   │                                                  ├── n metric_value  (指标值)
   │                                                  ├── n plot_task     (绘图任务)
   │                                                  └── n analysis_task (分析任务)
   │
   ├──────── n metric_config    (任务级指标参数)
   ├──────── n threshold_config (阈值：作用到 通道/设备/任务默认)
   ├──────── n alarm_ack        (超限记录与关闭留痕，v3 新增)
   └──────── n device_usage     (设备使用信息，v3 新增)

monitor_object (监测对象台账) 1 ── n sensor (传感器/台账)
metric_def (指标字典) 1 ── n metric_value / metric_config / threshold_config
```

> 语义调整（v3）：`monitor_object` 只到「监测对象（轴承/齿轮/电机）」这一级；**设备**（辊压机/分切机）由 `task_node(node_type=device)` 承载，与健康树保持一致。

### 6.2.2 导入时的指标计算口径（v4）

- **算不算**：数据接入页有「导入时计算指标」开关；关掉只做结构级校验（点数 / 采样率），
  只落数据集与通道文件，不写任何指标值。
- **算哪些**：以**健康树里该通道下挂的指标节点**为准（节点 `attrs["code"]` 或节点名），
  不再在代码里写死 v_RMS / a_Peak / a_RMS。
  - 通道下没有指标节点 → 该通道不产生指标值，导入结果里单独列出提醒。
  - 通道号对不上健康树 → 只入数据集，不写指标值。
- **同一通道号挂到多个监测对象**：计划表按「监测对象 × 通道」出多行；**方案 A（2026-10-31 拍板，见《指标参数体系与频率参数设计》§10）**：每个通道节点按自己的生效参数各算各的、按 `(channel_id, node_id, metric_code)` 各存一行；参数指纹与转速都相同的任务只真算一次、结果写多份节点行。
- 重导同一批次会按当前配置**重新计算并覆盖**该批次该通道的指标值（按 通道 × 计算时间点 upsert）。

### 6.2.1 主数据台账（v4 改造：台账 + 装配）

自 v4 起，**监测对象 / 通道 / 指标** 从「健康树节点」改为独立主数据台账，健康树只做**装配引用**，
从而实现「健康树里只做下拉选择，不手工输入」。

| 台账表 | 关键字段 | 说明 |
|---|---|---|
| `monitor_object` | `task_id, name, obj_type, part, remark, deleted_at` | 监测对象主数据；名称在任务内唯一 |
| `channel_reg` | `task_id, object_id(NULL=自由), code, remark, deleted_at` | 通道号在任务内唯一；`object_id` **可空**，NULL 表示这台通道/传感器当前不归属任何监测对象（自由态） |
| `metric_def` | `task_id, code, unit, params_json, enabled, deleted_at` | 指标码 + 单位 + 计算参数，与通道解耦 |

健康树节点（`task_node`）新增两列做引用：

| 列 | 说明 |
|---|---|
| `ref_type` | 引用哪张台账：`monitor_object` / `channel_reg` / `metric_def`（空=早期手工节点） |
| `ref_id` | 台账行 id |

约束与规则：

1. **节点类型决定可引用台账**：`component → monitor_object`、`channel → channel_reg`、`metric → metric_def`。
2. 引用不存在、或 `ref_type` 与节点类型不符 → `TreeError` 拒绝写入。
3. 台账软删除后，树上节点成为**悬空引用**，节点属性页显示「⚠️ 悬空引用」提示。
4. 台账与树同一事务内两次写入；迁移函数 `sync_from_tree`（对象/通道）与 `seed_defaults`（内置三指标）幂等，可从旧树一键补台账。
   **新建任务时页面自动调用 `seed_defaults`**（2026-11-03），新任务开箱就有 `v_RMS / a_Peak / a_RMS` 三条定义，健康树指标下拉直接可用；因此「指标配置」页不再提供「补齐内置指标」按钮；插件功能区上移到主区，与「指标台账」并列成为页面第三个区块（左插件台账 + 右插件详情 + 表下「重新扫描插件」），不再折叠在页面底部。
5. **装配唯一性按 `ref_id` 判**：监测对象全树唯一；**通道只在同一父节点下唯一**（同一通道可装配到多个监测对象，一条数据源被多对象共用）；指标定义同通道唯一。名字只是 `sync_ref_name()` 维护的显示缓存。
6. **树是归属的唯一真相**：`channel_reg.sync_ownership(task_id)` 按通道节点的父级监测对象反推 `object_id`，由 `create_node` / `update_node` / `reparent_node` 自动调用。多对象装配时保留当前值（不在其中取第一个）；树上已无该通道节点 ⇒ `object_id = NULL`（自由）。
7. **删装配 = 解绑**：`soft_delete_node` 把通道节点上的传感器 `node_id` 置空、行保持有效（留在台账当自由态），并把快照写进回收站 `payload["sensors"]` 留痕；资产本身绝不随装配一起软删。恢复时按 `id_map` 把传感器重新挂回新节点、并按父级写回归属。
8. **归属是绑定关系、不是身份属性**：自由通道/传感器可绑到任意监测对象；已绑定的可改绑（`tree.reparent_node` 挪节点，保留授权与阈值）或解绑（节点进回收站）。入口见 §9.6。
9. **转速、参数、阈值的落点**：额定转速 → `monitor_object.rated_rpm`（只有监测对象节点能录）；指标参数 → `metric_assign.node_id`（指标节点）；阈值 → `metric_limit.node_id`（指标节点）；指标值与 stale 标记仍挂 `metric_value.node_id`（通道节点）。

**三张台账页面与健康树的分工**：三页管主数据（自由态增删改、归属绑定、批量操作），健康树管「哪台设备下装了哪个对象、哪个对象用了哪个通道、通道上算哪些指标、参数与阈值怎么定」。同一件事只给一个入口——例如转速只在监测对象节点、指标参数只在指标节点。

### 6.3 软删除（决策 5 落地）

**语义**：删除 = 把父实体与所有子孙在同一事务内写 `deleted_at`，不是物理删除。

| 删除对象 | 同步标记删除 |
|---|---|
| `dataset` | 其 `channel` → 各 channel 的 `metric_value`、`plot_task`、`analysis_task` |
| `channel` | 其 `metric_value`、`plot_task`、`analysis_task` |
| `test_task` | 其 `dataset`（及上述全链） |
| `monitor_object` | 其 `sensor`、`threshold_config`；关联 dataset 不删（界面提示"该对象下仍有 N 个数据集"） |

**实现约定**：

1. 每张业务表带 `deleted_at TEXT NULL`，`NULL` = 有效。
2. 所有查询走 Repository 默认追加 `WHERE deleted_at IS NULL`，页面不得手写裸 SQL。
3. 唯一约束遇软删除：重算/重建时对已有行执行 `UPDATE ... SET deleted_at=NULL` 复活，不新插重复行。
4. 物理删除只发生在回收站"彻底删除"，此时由外键 `ON DELETE CASCADE` 兜底清子表。
5. 删除前预览必须查真实计数：`数据集1 / 通道3 / 指标值27 / 绘图任务5 / 分析任务2`。
6. 原始 `.dat` 文件默认**不动**（只删索引）；彻底删除时勾选才删文件。

### 6.4 事务与一致性

- 每次操作一个事务（`BEGIN IMMEDIATE`），失败整体回滚。
- 连接建立即 `PRAGMA foreign_keys = ON`（SQLite 默认关闭，漏了外键形同虚设）。
- 删除后校验受影响行数，与预览数字不一致则回滚并报错。

## 七、有效性判定接口（决策 3 落地）

判定逻辑与"怎么判"解耦：本期只定接口和数据结构，业务判据后续插入。

```python
class ValidityLevel(StrEnum):
    PASS = "pass"; WARN = "warn"; FAIL = "fail"

@dataclass(frozen=True)
class CheckResult:
    name: str                  # "结构完整性" / "直流偏置" ...
    level: ValidityLevel
    note: str                  # 人类可读原因
    metrics: dict[str, float] | None = None

@dataclass(frozen=True)
class ValidityReport:
    level: ValidityLevel       # 取所有 check 的最严重级别
    checks: list[CheckResult]

class ChannelValidator(Protocol):
    name: str
    def check(self, ctx: ChannelContext) -> list[CheckResult]: ...
```

| 组成 | 本期状态 |
|---|---|
| 接口与数据结构 | **实现**（`ValidityLevel` / `CheckResult` / `ValidityReport` / `ChannelValidator`） |
| 校验器注册表 | **实现**（`configs/validators.yaml` 列出启用的校验器） |
| 结构级校验 `StructureValidator` | **实现**：文件头/长度/采样率非零/无 NaN/非死通道（复用 Reader 已有能力） |
| 业务判据（直流偏置、饱和率、峭度、通道-传感器匹配、采样率一致性） | **不实现**，仅留扩展点；界面显示"业务判据未配置（待扩展）" |
| 汇总规则 | 有 FAIL → FAIL；有 WARN → WARN；全 PASS → PASS |

## 八、阈值与两级告警（决策 4 落地）

### 8.1 作用域（v5：统一配到指标节点）

```
指标节点（「通道 × 指标」）  >  通道  >  监测对象  >  设备  >  测试任务
```

- **所有阈值统一配置在健康树的指标节点上**（马哥 2026-10-30 定），即「通道 × 指标」这一级；
  来源列显示 **「指标级」**。
- 继承链仍保留：指标节点没配时向上找通道 → 对象 → 设备 → 任务，命中第一个有值的节点；
  都没配 = 不告警（`level = NULL`，显示"未设阈值"，不默认判 ok）。
- 历史遗留的通道级阈值行由 `db.migrate_limits_to_metric_nodes()` 在 `init_db` 时自动迁到对应指标节点，幂等可重复执行。

### 8.2 判定规则（方向口径，2026-10-31 定）

阈值按「方向 + 两级门槛」存一行。**`warn` 是级别更轻的门槛，不是「数值更小」的门槛**（马哥 2026-10-31 拍板，替代早期「一律 warn < alert」的硬校验）：

| 方向 | 库里存 | 合法关系 | 判级 |
|---|---|---|---|
| 上限（越大越差） | `>` | `warn < alert` | 值 ≥ warn → warn；值 ≥ alert → alert |
| 下限（越小越差） | `<` | `warn > alert` | 值 ≤ warn → warn；值 ≤ alert → alert |

顺序：先判 alert，命中即 alert；再判 warn；否则 ok。**未配置任何阈值 → `level = NULL` 并显示"未设阈值"，不默认判 ok**（避免假安全）。**值非有限（NaN / ±Inf）→ 不参与比较，页面显示「数据异常」，绝不显示「正常」**（2026-10-31 修复 G10：`grade` 返回 `unset`、`point_level` 返回专门状态 `invalid`，见 §14.3）。

- **规则唯一实现**：`src/lion_monitor/limits_rules.py`（`validate_limit()` 校验、`grade()` 判级）。阈值写入（`store/limits.set_limit`）、模板 v2 导入/导出、阈值设置页校验、健康评级（`features/health.point_level`）、趋势着色与超限记录**全部调它**，不得各写一套。
- 方向写法兼容：`>` / `upper` / `<` / `lower` 都认；读路径认不出的方向按上限口径处理（不炸页面），写路径未知方向直接报错（不猜）。
- **老数据只提示、不改数**：库里 `direction="<"` 的老行照常读；若与方向口径不符（如 lower 但 `warn ≤ alert`），阈值页列出「请人工确认」，迁移/读取都不动数值。

#### 9.10.1 阈值可单边设置（2026-11-04 马哥：只设 warn 或只设 alert）

**旧限制**：warn / alert 必须同时填（否则页面报「warn 与 alert 要同时填」），
数据层 `validate_limit` 又要求 warn < alert，于是「只关心一条线」的场景只能靠填 0 绕过，
而 0 在 `grade()` 里是**真门槛**（值 5 就被判预警），语义错。

**新口径：`0 = 该档未设`**，不算门槛。

| 配置 | 判级效果 |
|---|---|
| warn=9，alert 留空 | 值 ≥9 → 预警；**永不告警** |
| warn 留空，alert=9 | 值 ≥9 → 告警；**没有预警档**（越过直达告警） |
| 两侧都填 | 三级：健康 / 预警 / 告警 |
| 两侧都空 | = 删除该行阈值，回到继承 |

改动点：

| 文件 | 改动 |
|---|---|
| `limits_rules.validate_limit` | 两侧都 0 → 报「至少填一个」；单边 → 直接通过；两侧都有值才校验 warn<alert / warn>alert |
| `limits_rules.grade` | `if alert and value >= alert`、`if warn and value >= warn` —— 0 档永不命中 |
| `features/health.point_level` | 两侧都 0（历史遗留行）→ 返回 `unset`（未设阈值），不许判成「正常」 |
| `app/pages/thresholds.py` | 允许单边填；留空侧记 0；列 help 改「留空=该档不判」；表下提示补单边口径；回显未设侧为**空**而不是 `0` |
| `store/tree_template.py` | 模板导入：`阈值必须大于 0` → `不能为负`（0 合法，两侧都 0 由 validate 拦） |

**实测**（临时库 `/tmp/one.db`）
- 数据层：`v_RMS warn=0.1/alert=0` → state `warn`（值 10.52 也不告警）；`a_Peak warn=0/alert=0.001` → state `alert`；
- 阈值页回显：`CH2 v_RMS [0.1, 空]`、`CH2 a_Peak [空, 0.001]`、`CH2 a_RMS [1, 1.4]`；
- 工作台待办：`🟠 振动超限 … v_RMS · 预警` 与 `🔴 振动超限 … a_Peak · 告警` 并存 —— 单边设置真的各按各的判。

**影响面**：正式库 `metric_limit` 现有阈值行全是双填正数，引入「0=未设」不改任何历史判级，无需迁移。

**FFT 幅值显示方式（v5 确定）**

- FFT 页签增加「幅值」下拉：**峰值 Peak**（默认）/ **有效值 RMS**。
- 峰值：谱线值为该频率正弦分量的幅值（单边谱，已按窗函数相干增益归一）。
- 有效值：`RMS = Peak / √2`，用于与 v_RMS 这类有效值指标直接对照。
- 包络谱暂不提供该开关（幅值恒为峰值口径）。

**FFT 幅值谱计算口径（v5 实现，2026-10-30）**

- 对选中区间**整段一次 FFT**（不叠段、不设重叠率），出**单边幅值谱 0 ~ fs/2**，
  分辨率 `Δf = fs/N`；区间 20 s / 32 kHz 时 `N = 640,000`、`Δf = 0.05 Hz`。
- 窗函数六选一：汉宁（默认）/ 平顶 / 海明 / 布莱克曼 / 凯泽（β=8.6）/ 矩形；
  幅值按**窗函数相干增益**归一 `|X|·2/(N·cg)`（`cg = Σw/N`，直流分箱不翻倍），
  所以换窗后同一正弦的峰值不变（矩形窗与汉宁窗差异 < 2%）。
- 主峰用 **▲** 标注频率/幅值，并在图上方一行列出前几个峰：
  只收**相对主峰 ≥ 1%（-40 dB）**的显著峰，峰间距至少 5 个分箱（避免同一主瓣采成多峰），最多 5 个。
- CSV 固定两列 `频率 (Hz),幅值 (g)`，逐频点导出（0 ~ fs/2），不受峰筛选影响。
- 实测口径（`DS-20261029-002` · CH2，20 s）：幅值谱主峰 **172.05 Hz / 1.005 g**；
  145 Hz 处幅值仅约 `1e-5 g`——145/290 Hz 是**包络谱**特征（见 ③ 包络谱），不是幅值谱主峰。

**包络谱算法（v5 确定）**

- 包络方法**固定为希尔伯特（解析信号模）**，界面上既不给下拉、也不显示任何「包络方法」文字（马哥要求去掉）。
- 参数只剩：带通下限 / 带通上限 / ☑ 去均值（与 FFT 页签同一样式的复选框，默认勾选，作用对象是包络信号）。
  **「滤波器阶数」已删除**（马哥 2026-11-03：包络谱滤波改用频域滤波，复用已有算法，频域置零没有阶数这个概念）。
- 依据（CH2 实测，2–10 kHz 共振带、20 s）：
  - 希尔伯特 vs 整流+低通：包络谱 1–500 Hz 形状相关 **0.998**，主峰位置完全一致
    （290.1 Hz = 2×145、145.05 Hz = 1×），诊断结论相同；
  - 但整流法幅值系统性偏低约 40%，且**在全频带（默认 0–fs/2）下会产生假峰**
    （290 Hz 处 0.169 vs 希尔伯特 0.0011，差约 150 倍），容易误判；
  - 整流+低通需要额外选低通截止、多一个调错的维度，故不保留。

**包络谱计算口径（v5 实现，2026-10-30）**

- 链路：**频域带通**（`features.filters.bandpass_freq`：`rfft` → 带外置零 → `irfft`，与指标层 v_RMS/a_RMS 同一实现，零相位、无暂态、无阶数）→ 希尔伯特取模得包络 →
  （去均值）→ 整段一次 FFT → 包络谱 0 ~ fs/2 + 主峰 ▲ + 目标频率/阶次竖线 + 逐频点 CSV。
- 带通边界语义：**下限 0 且上限 fs/2 = 全频带，等效不做带通**（默认参数）；只给上限 → 低通；
  只给下限（上限 fs/2）→ 高通。阶数 2~10 可调、默认 4。
- 非法参数（上限 ≤ 下限、边界为负、上限 > fs/2、阶数越界）**直接抛错**：页面给告警
  「带通上限必须大于下限，包络谱不计算」并把「运行包络谱」置灰，不会出 NaN 图。
- 幅值口径与 ② FFT 页签一致：汉宁窗 + 相干增益归一 `|X|·2/(N·cg)`，幅值恒为**峰值 Peak**
  （包络谱不给有效值开关）；去均值作用于包络信号，0 Hz 直流峰消失而 145/290 Hz 幅值不变。
- CSV 固定两列 `频率 (Hz),幅值 (g)`，逐频点导出（0 ~ fs/2）。
- 实测口径（2026-10-30 复核，20 s 整段）：145/290 Hz 这一对特征线出现在
  **`DS-20261029-001` · CH2（15:28:34 批次）**——2–10 kHz 带通、阶数 4 时包络谱峰
  **145.05 Hz / 4.1e-5 g** 与 **290.10 Hz / 1.07e-4 g**（290 Hz 为 2×145，最强）；
  全频带（不做带通）时两者幅值为 145.05 Hz / 2.3e-3 g、290.10 Hz / 2.1e-3 g。
  `DS-20261029-002` · CH2（16:03:13 批次）在 2–10 kHz 带通下的最强包络线是 **344.15 Hz
  （≈ 2×172 Hz 轴系）**，145/290 Hz 处无显著线——卡片里写的「DS-20261029-002 CH2 出
  145/290」与实测批次差了一条，按实测断言。

**数据集对比规则（v5 确定）**

- 常规视图一个数据集；对比行**紧贴数据源行下方、不折叠**，四列与上方 A 行同宽对齐，
  **隐藏标签文字（label_visibility="collapsed"）以省高度**，靠列对齐表达含义。
- 「数据集 B」首项为「— 不对比 —」，选中其它项即开启对比，**允许与 A 相同**

- 采样率等信息**不单独占行**，统一并进底部一行：
  `当前查看：DS-… · 通道 · fs 32000 Hz · 20.00 s ｜ 对比 DS-… · 通道 · fs 32000 Hz · 20.00 s`。
- 三个页签叠两组曲线，图位标题带「｜ 对比 …」；窗函数、带通、标记线共用，时间区间各自独立。

**图上标记规则（v5 确定）**

- FFT 与包络谱的标记区只保留两项输入：**目标频率 (Hz)**、**阶数**；不再输入参考转速。
- 阶次换算基准 `f0` = 「目标频率」里填的**第一个值**（由用户手动输入基准频率），
  第 n 阶画在 `n × f0`；只填阶数、未填目标频率时提示先填基准频率。
- 图上呈现：目标频率画竖线并标数值；阶次竖线标注 `n×` 与该阶对应频率。

**波形抽稀规则（v5 确定）**

- 「显示上限点数」默认 1,000,000：区间点数 ≤ 上限 → 原样逐点画，不抽稀。
- 超过上限 → **最小/最大包络抽样**：把序列按等长分箱，每箱取最小值与最大值两点画线，
  保证冲击/尖峰不会被跳过（等间隔抽样会漏峰，不采用）。
- 抽稀只影响绘图；CSV 导出始终为原始逐点值。

## 十、算法清单（scipy.signal / numpy 封装）

| 类别 | 指标 | 实现 |
|---|---|---|
| 时域 | RMS、均值、标准差、峰值、峰峰值、偏度、峭度、波峰因数、脉冲因数、裕度因数 | numpy 纯计算 |
| 速度 | 速度有效值 v_RMS（带通 10–1000 Hz → 频域积分 → 有效值，mm/s） | `rfft` 带外置零 + `rfft` 积分（S4D 起不再用 `butter`） |
| 频域 | 幅值谱、主频与幅值、频带能量、频谱重心 | `welch` / `rfft` + `find_peaks` |
| 包络 | 带通滤波、Hilbert 包络、包络谱、包络主频、边频带 | `butter` + `sosfiltfilt` + `hilbert` |
| 时频 | STFT | `spectrogram` |

约定：纯函数（数组+参数 → 结果）；参数 pydantic 校验；`params_hash` = 参数 JSON 的 sha256 前 12 位。

### 10.1 v_RMS 计算口径（S4D 起，2026-11-02）

原「4 阶 Butterworth + `sosfiltfilt`」已删除（阶数、零相位补边、边缘暂态一堆设置），
带通改为整体频域处理，与频域积分合成一条链路：

1. **频域带通（带外置零）**：`np.fft.rfft(x)` → 频率不在 `[band_low, band_high]` 的频点置零
   → `np.fft.irfft(n=原长度)`。零相位、无延迟、无 IIR 暂态，返回长度与输入一致；
   没有「滤波器阶数」这个参数。**硬截断**（不做余弦过渡带）：实测 1000 Hz 通带增益 1.0000、
   1010 Hz 已是 0.0000，1200 Hz 单音过 10–1000 Hz 带通后残留 **-267.5 dB**，无需过渡带；
   代价是段首尾接缝处的 Gibbs 振铃，故保留「切首尾各 0.5 s」——145.3 Hz（非整周期）2 s 段
   接缝处逐点偏差 0.297 g，切 0.5 s 后降到 1.4e-3 g，RMS 不受影响（比值 0.99995）。
2. **上限夹紧**：生效上限 = `min(band_high, fs/2 × 0.95)`（`BAND_CLAMP_RATIO`）；下限按 Q9
   硬下限 2 Hz、窗长装不下 10 个周期时按窗长抬高。计算、`params_hash`、落库快照共用同一份夹紧值。
3. **频域积分转速度**：带内频谱乘 `G_TO_MM_S2 / (jω)`（g→mm/s²，9806.65）后逆变换回时域。
   频域积分不累积漂移、不放大带外噪声。
4. **RMS 为去均值后的 AC 口径**：`v_RMS = sqrt(mean(v²))`，输入先去均值（`detrend` 默认开）。
   逐窗路径按 `window_s`/`step_s` 切窗，窗函数在带通、切首尾之后作用并按系数 RMS 归一化。
5. **实测**：145 Hz / 0.8 gpk / fs=32 kHz / 20 s → `v_RMS` = 6.089025518512 mm/s，理论值
   `0.8/√2 · 9806.65/(2π·145)` = 6.089025518512（相对误差 2.9e-16）。

**加窗口径（2026-11-02 实测拍板，fs = 32 kHz、窗长 2 s）**：

| 指标 | 加窗 | 实测依据 |
|---|---|---|
| `v_RMS` | **要**（Hanning） | 97.3 Hz 非整周期：不加窗 5.748 vs 理论 5.671（+1.34%）；加 Hanning 5.672（+0.01%）。频域积分除以 ω 会放大低频泄漏，所以先加窗再积分，并按 `√mean(w²)` 归一化 |
| `a_RMS` | **不要** | 带通后只取带内能量，加不加窗差 ≤ 0.02%（0.6054623 vs 0.6041261 量级差异可忽略） |
| `a_Peak` | **绝对不能** | 加窗会把峰值压低，峰值类指标失真 |

试过用「频域过渡带渐变」代替时域窗，实测更差（99 Hz 过渡带把 33.7 Hz / 60 Hz 分量一起削掉），不采用。

**a_RMS 同样带通**（马哥 2026-11-02）：「频域带通置零 → 有效值」（`metrics._band_rms`），
参数 `band_low` / `band_high`（默认 10–1000 Hz），与 `v_RMS` 共用 `effective_params` 夹紧规则
（硬下限 2 Hz、上限 `fs/2 × 0.95`、窗长装不下 10 周期自动抬高）；样本太短带通不可用时退回裸 RMS，
不静默出 0。整段与逐窗两条路径都走它。`detrend=False` 不再能把直流算进 `a_RMS`（直流在带外）。

> 包络谱（§9.12）2026-11-03 起也改用同一个频域带通（`features.filters.bandpass_freq`），
> 阶数参数已删除；0–fs/2 仍表示全频带（等价不滤波）。

### 10.1.1 重算与旧值作废（2026-11-02）

- 逐窗产点上线**之前**算的值是「整段一个值」，特征是 `metric_value.node_id IS NULL`、`params_hash=''`、
  `computed_at` = 记录起始时刻、每条记录 1 行。
- `metrics.replace_node_series` 原先只作废「本节点且 `stale=1`」的旧点，`node_id` 为 NULL 的行
  永远不会被清掉 → 趋势变成 N+3 点（多出卡在记录起点的旧值）。
- 现在重算会**顺带软删同通道同指标、`node_id IS NULL` 的遗留行**；给旧值标 `stale=1` 不再是清不掉的死路。
- 口径变更（如 a_RMS 加带通）后必须把受影响的 `metric_value` 标 `stale`，再在数据接入/趋势页重算。

### 10.3 自定义指标算法（插件机制，2026-11-03）

内置算法只有三支（`v_RMS` / `a_Peak` / `a_RMS`）。要加新算法**不改项目代码**：往插件目录放一个
`.py` 文件即可，改完存盘自动热加载（按文件 mtime 判断，无需重启服务）。

**插件目录**：`~/.lion_monitor/metrics_plugins/`（首次访问自动创建；可用环境变量
`LION_METRIC_PLUGINS` 覆盖）。示例见 `docs/examples/metric_plugins/kurtosis.py`。

**接口（由我们定义，插件只实现这几个名字）**

| 名字 | 必填 | 含义 |
|---|---|---|
| `CODE` | 是 | 指标码，字母开头 2–64 字符；不能与内置重名（冲突只跳过该文件并报错） |
| `compute(window, sample_rate, params)` | 是 | 入参：一个窗的 `numpy.ndarray[float64]`（**已去直流**）、采样率 Hz、该节点生效参数 dict；返回：`float` |
| `UNIT` | 否 | 单位（趋势纵轴 / 阈值显示） |
| `TITLE` | 否 | 中文名（界面展示） |
| `DESCRIPTION` | 否 | 一句话说明 |
| `PARAMS_SCHEMA` | 否 | 参数声明数组，决定指标节点上渲染哪些输入框（与内置 schema 同格式） |

**操作步骤（用户视角）**

1. 把插件 `.py` 放进插件目录；
2. 「指标配置」页 → 主区第三块「🧩 自定义算法（插件）」→「重新扫描插件」，能看到码 / 中文名 / 参数项；
3. 「新增指标」里**指标码下拉**直接选它（单位与参数声明自动带出，可改）→「创建指标」；
4. 健康树 → 通道节点「监测指标」装配该指标 → 指标参数里调 `window_s` / `step_s`；
5. 「数据接入」重算或导入新数据，逐窗出点，趋势页可见。

**失败与兜底（不静默）**

| 情况 | 行为 |
|---|---|
| 插件缺 `CODE` / 缺 `compute` / 导入报错 | 只跳过该文件，页面黄色告警列出文件名与原因，其他指标照常 |
| 插件 `CODE` 与内置同名 / 两个文件同码 | 跳过并报错，不覆盖内置 |
| `compute` 抛异常 / 返回 NaN·Inf / 返回非数字 | 该文件判为计算失败并写明原因（不写 0，不静默） |
| 指标码没有任何算法（既非内置也无插件） | 计算计划里跳过，原因「没有对应算法（插件目录 … 里也没有这个码）」，趋势不会出现假 0 |

**口径**：`compute_metric_series(codes=None)` 仍只算内置三指标（结果不随用户插件目录变化，便于回归）；
插件码必须由调用方显式传入 —— 生产路径（导入 / 重算 / 趋势）都是逐个指标节点显式传 `codes=[码]`。

**导入与删除（UI，2026-11-03）**

| 动作 | 位置 | 语义 | 拦截 |
|---|---|---|---|
| 从台账移除 | 指标详情卡底部 | 软删 `metric_def` 行，**算法实现保留** | 仍装配在健康树上时拒绝 |
| 导入算法 | 插件区「＋ 导入算法（.py）」（可多选，一次导入多个） | 上传 `.py` → 校验 → 落盘插件目录 → 立即可用 | 空文件 / 非 `.py` / 缺 `compute` / CODE 非法 / 与内置重名 / 码被别的文件占用 → 报错且不落盘；同名文件需勾「覆盖同名文件」 |
| 删除算法 | 插件区「删除算法（.py）」 | 删插件文件，两次点击确认（确认态红色） | 台账还有任务在用这个码时拒绝，并列出「任务号 · 任务名」 |

**实测（副本库，2026-11-03）**：放入 `kurtosis` 插件 → 建指标 → 装到 CH1 → 重算，
`3 条记录 × 10 窗 = 30 点`，值域 `2.84 ~ 3.19`（高斯噪声理论值 3），`unit` 为空按插件声明。
