## 5. 问题清单（分级）

### 阻塞（结果错 / 崩溃）：0 条

现场 3 批次全部「有效」，36 行指标值齐全，页面 0 异常，模板往返等价 —— 没有结果错误或崩溃。

### 严重

**S-1 阈值方向「越小越差」（`<`）保存必失败，阈值页该方向不可用**
- 页面口径（`app/pages/thresholds.py`）对 `direction == "<"` 要求 `warn > alert`；但 `limits.set_limit` 硬校验 `warn < alert`，两者冲突 → 写入必抛 `LimitError`。
- 证据（`…probes.txt` P3）：
  ```
  warn=0.5 / alert=0.2（< 方向，页面口径要求 warn>alert）→ LimitError: warn 必须小于 alert（收到 warn=0.5, alert=0.2）
  ```
- 影响：模板 v2 的阈值导入只能绕过 `limits.set_limit`（`tree_template` 里按方向自行校验后 upsert），而**阈值设置页仍然写不进去**；上下限类指标（如间隙、温度下限）无法配阈值。
- 本轮未修（属既有缺陷，按约定只记录）。
- **状态：已修（2026-10-31，S-1）**。口径按马哥拍板改为「按方向校验」（`upper` 要 `warn < alert`、`lower` 要 `warn > alert`），规则抽到单一来源 `src/lion_monitor/limits_rules.py`，`set_limit` / 阈值设置页 / 模板 v2 / 健康评级统一调用；老库 `direction="<"` 的行照常解析、数值不改，方向与数值关系不符的行只在页面提示人工确认。设计文档 §8.2 / §8.3 / §12-11 / §12-12 已同步，实跑证据 `reports/2026-10-31-s1-direction-limits.txt`（六条验收全 PASS，全量 485 passed）。

**S-2 批次里一个文件损坏/截断 → 整批导入中断，并残留「待判」空数据集**
- `features/pipeline.py::import_batch` 第 330 行 `read_vibration(f.path)` 无异常保护：任一文件读失败直接抛出，该批次**其余有效文件也不落库**；`import_from_dir` 已建的数据集记录留下来（状态「待判」、1 个文件、0 值）。
- 证据（`…probes.txt` P8）：
  ```
  抛出 VibrationFormatError：…CH1_Task1.dat: 文件长度不一致，头部声明 640000 个样本应为 2560512 B（512 B 头 + 640000×4 B）…
  导入前数据集 7 个 → 导入后 8 个
  新增的：[('DS-20261031-009', '待判', 1)]
  ```
- 影响：现场常见「拷贝中断/磁盘满」的半截文件，会让整批数据进不来且库里多一条空数据集；页面只弹错误文案，用户容易以为没导入成功却留下垃圾记录。

### 一般

**G-1 静默通道的 FFT / 包络谱「主峰」落在 0.05 Hz，页面无判据直接显示**
- 证据：§3 表中 CH3/CH4 三批次主峰均为 `0.05 Hz`（幅值 0.0001–0.0007 g），因 `fft_spectrum` 只做 demean（保留 bin1 的慢漂移），`top_peaks` 没有下限频率，静默通道就把漂移当主峰。
- 设计 §2.6 的选峰带宽（f<50 Hz 取 ±1 Hz、f≥50 Hz 取 ±3%、包络 ±5%）与「目标频率处是否显著」判据尚未落代码，页面直接取全局最高峰 → 用户会以为设备有 0.05 Hz 特征。

**G-2 改指标参数后历史值不重算，只标 `stale=True`**
- 证据（`…probes.txt` P4/P5）：`band_high` 2000 → 500 后，CH2·v_RMS 最新值仍是 `10.52722 mm/s`（`stale=True`，`params_hash=c24195c9e3ff`）。属 S4 未做范围，本轮按约定不实现，但趋势页会拿旧值画线。

**G-3 传感器灵敏度只进台账，不参与换算；「传感器」页文案却称是换算依据**
- `ingest/vibration.py:213` 注释：「值本身已是加速度 g，传感器灵敏度（如 500 mV/g）只作台账记录」；`app/pages/sensors.py:42` 文案：「型号与灵敏度是后续换算 g 值的依据」。两处口径不一致。
- 本次数据是 g 单位，不受影响；若接入 mV 原始数据，值会差 2 倍（500 mV/g）而无任何提示。

**G-4 导入模板会把任务根节点名改成模板里的名字**
- 证据：A 验收与现场模板导入均出现「结构与源任务一致 True」，但目标任务根节点名 = 模板根名（「卷绕产线振动监测」），不是目标任务名（「复查导入任务」）；`tests/test_tree_template_v2_refs.py` 已按此口径断言。
- 与 v1 行为一致（整树替换），但跨任务导入后用户会看到根节点名与任务名不一致，无提示。

### 建议

**T-1 导入结果增加「缺通道 / 多通道」对照提示**
- 证据（`…probes.txt` P7）：树上 4 通道、文件只有 3 个 → `status=有效 channels=3 files_ok=3 unmapped_channels=[]`，没有任何「缺 CH4」提示（`ImportResult` 只覆盖「文件里有、树上没有」的 `unmapped_channels`）。
- 建议报告里补 `missing_channels`（树上配了但本批次没文件），并在页面提示。

**T-2 主峰判定加下限频率与显著峰判据**
