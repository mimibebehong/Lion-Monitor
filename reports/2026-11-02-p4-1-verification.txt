迁移容错（老库里已有「同键且都未软删」的重复行）实测：
  tests/test_store_partial_unique_indexes.py::test_init_db_migrates_legacy_unique_constraint
  用真实老 DDL（``CONSTRAINT uq_metric_assign UNIQUE (node_id, metric_code, deleted_at)``）
  造库，metric_assign 塞 3 行同键未软删 + 1 行已软删，metric_limit 塞 2 + 1，跑 init_db 后：
    before == (4, 3) 且 after == before（行数一字不差）
    同键生效行 kept_assign == [(1,)]、kept_limit == [(1,)]（保留最小 id）
    迁移后同键未软删再插 -> UNIQUE constraint failed: metric_assign；软删后可重插
  pytest 捕获到的引擎日志：
  WARNING lion_monitor.store.db: metric_assign: 迁移部分唯一索引时发现同键重复行 2 条，
          已按 id 保留最小的一条、其余置 deleted_at（未丢数据）
  WARNING lion_monitor.store.db: metric_limit: 迁移部分唯一索引时发现同键重复行 1 条，
          已按 id 保留最小的一条、其余置 deleted_at（未丢数据）
  选择「软删不丢数据」而不是直接报错：行数前后完全一致，最小 id 保持生效、
  其余置 deleted_at；同时 logger.warning 记条数，操作员可回溯。
  老约束下不能先改 deleted_at（同键多行会撞 (键列, deleted_at)），所以去重放在
  重建表的 INSERT ... SELECT 里做：只有同键最小 id 保持 deleted_at IS NULL。
