一、做了什么
--------------------------------------------------------------------------------
1. 导出（src/lion_monitor/store/tree_template.py）
   - 文件头新增 `params_snapshot: true`（版本号仍是 version: 2，纯增量可选字段）
   - 已绑定的 metric 节点新增 `effective_params`：该节点实际生效的完整参数快照，
     口径直接复用 metric_assign.compose_params（与页面展示 / 计算层同一个函数）
   - 未绑定（bound=false）的节点不写快照：没有绑定就没有生效值
2. 导入（同文件 _apply_params / import_template）
   - ImportOptions.param_strategy 三选一：override（默认）/ locked_only / follow_default
   - override：落库的是「目标任务定义默认 → 模板生效值」的 diff（目标侧再叠默认仍等于模板生效值），
     locked 标志仍随模板走，不偷偷把未固化节点变成固化
   - locked_only：只对模板里 locked=True 的节点按生效值搬，其余保持旧行为
   - follow_default：旧行为（只搬覆盖 diff）
3. 预览（同文件 _param_diffs / preview_import）
   - ImportPreview.param_diffs 逐项给出「节点路径 × 指标码：参数 目标默认 → 模板生效值」
   - 新增 param_diff_count / param_diff_nodes / has_snapshot；旧 v2 文件给 SNAPSHOT_MISSING_NOTE 提示
4. 页面（app/pages/health_tree.py）
   - 导入浮层预览区显示「N 个指标参数与目标任务默认不同（涉及 M 个指标节点）」并可展开明细
   - 新增「参数策略」单选（按生效值搬运 / 只搬固化项 / 只搬覆盖差异），无快照时置灰
   - 导入报告增加「按生效值搬运参数 N 个指标」与 notice 文案
5. 口径复用（src/lion_monitor/store/metric_assign.py）
   - 新增公开包装 definition_defaults()（内部 _definition_defaults 原样保留），
     模板层算漂移与搬运 diff 都走它，不另写一份默认口径

九、版本号与兼容规则（结论）
--------------------------------------------------------------------------------
模板仍写 `version: 2`，不用 v3：
  - version 1            → 旧 id 逻辑（不变）
  - version 2 + params_snapshot: true → 三策略可用，默认 override
  - version 2 + 无 params_snapshot    → 强制 follow_default 并提示（即使传了 override）
  - version 2 + effective_params 非对象 → 校验报错
理由：v1→v2 的差异是引用口径不兼容（自增 id vs 业务键），必须靠版本号分派；本次是纯增量字段，
旧文件缺字段时的行为恰好就是旧行为，不需要新分派分支。
